Settings and presets

Settings is where you decide how a chat talks to its model and what it says: the connection, the samplers, the pieces of the prompt, who is talking and which lore books are in play. Every chat carries its own copy of these choices, and the Library holds the presets they start from. This page explains how the two fit together, then walks every tab.

How settings work

Type /settings to open the screen. Its title reads Settings followed by the version, and the pane on the left lists the tabs: General, Appearance, Connection, Samplers, Prompt, Participants and Lore. The Samplers tab appears once a provider is chosen, because the samplers on offer depend on the protocol that provider speaks.

What you are editing depends on where you opened it from:

  • With a chat open, Settings edits that chat and nothing else. Two chats can use different models, personas and lore books at the same time.
  • With no chat open, Settings edits the defaults that every new chat starts from. This is what you see on first run, when Ashyo opens the Connection tab with the notice "Set up a connection to start chatting."

General and Appearance are different: they are about the app, not about a chat, so they are global and take effect the moment you change them.

The Connection, Samplers, Prompt and Participants tabs show a status line reading "No unsaved changes." or "N unsaved changes." That count is the number of values you have changed away from the selected preset. The chat remembers them, so nothing is lost when you leave; "unsaved" means they have not been written back into the preset yet. See Presets.

Changing a chat's settings refreshes its connection details in the background. It may also add or remove a greeting: picking a character on an empty chat seeds its greetings, and picking a different one removes them. See Greetings.

Overrides

Every value on the Connection, Samplers, Prompt and Participants tabs comes from a preset. When you change one of those values in Settings, you are not editing the preset. You are giving this chat, or the defaults, an override that wins over the preset's value.

  • Overrides are marked. An overridden row gets a ∗ before its label and a note under it showing what it is overriding: "Inherits: X" on connection rows, "Default: X" on sampler rows, and "Preset: X" on the system prompt and participant rows.
  • Reset puts it back. Press Tab on an overridden row and choose Reset to return to the preset's value. On a row that is not overridden there is no Reset, and asking for one is refused with "Nothing to reset."
  • Matching values are not overrides. If you set a value equal to what the preset already says, the mark disappears.
  • Switching clears. Choosing a different connection preset or a different provider drops every connection override. Choosing a different persona or character drops that participant's overrides.
  • Empty connection fields fall back to the provider's own defaults, such as KoboldCPP's address and port.
  • Samplers need a provider. Changing a sampler before a provider is chosen is refused, since Ashyo cannot know which samplers apply.
Tip

Overrides are how you experiment. Try a higher temperature or a different system prompt in one chat without touching the preset every other chat uses. When you like the result, save it into the preset or save it as a new one.

Presets

Each of these sections starts with a Preset row showing which Library item it uses. Connection presets list as "name · provider · protocol". Where it makes sense the list offers None; when there is nothing to choose, the row notes "No saved presets." Press Enter on the row to pick, or Tab to see its actions:

  • Save. Writes your overrides into the selected preset and clears them, so every chat using that preset picks up the change. Offered only when a preset is selected and you have changes. Context and instruct templates never offer it, because their fields edit the template directly (see Prompt). Saving a connection with no provider is refused.
  • Save as. Asks for a name, suggesting "Untitled", then makes a new preset from the current selection plus your overrides and selects it. This is the usual way to turn a good experiment into something reusable.
  • Rename. Renames the selected preset. Every chat that uses it follows the new name.
  • Delete. Asks "Delete preset?" For a persona or character it asks "Delete name?" and warns "Chats using this persona will switch to User." or "Chats using this character will switch to Assistant." The default answer is Keep. The built-in User and Assistant cannot be deleted.
  • Reset all and Neutralize, on the sampler Preset row only. Reset all drops every sampler override and returns to the preset. Neutralize sets every sampler to its built-in default value, which is a quick way to start from a known place. See Samplers.

After Save or Save as, "saved preset" shows on the status bar for a few seconds.

If you pick a different preset while you still have unsaved changes, Ashyo asks what to do with them: Discard and switch, Save then switch, or Cancel. Save then switch is offered only when there is a preset selected to save into.

Presets and chats stay in step. Renaming a preset or a lore book updates every chat that selects it, including chats on disk. If a chat names a preset that has since been deleted, it falls back to that kind's default when it is next opened, missing lore books are dropped from its list, and a provider that no longer exists is cleared.

General

Two rows, both global and applied at once.

  • Close idle chats after. Whole hours, 4 by default. A chat you have left open in the background is closed quietly once it has been idle this long, which frees its memory. 0 keeps every chat open. See Open chats.
  • Log level. One of off, error, warn, info (the default), debug and trace. The help text says it all: "Choose how much Ashyo records in ashyo.log and the log viewer. Off records nothing." See Log level.

Connection

This tab holds the route to your model: a Preset row, then Provider and Protocol under Route, the address or base URL under Endpoint, an Account with its API key or login under Authentication, the Model, any Extra request fields, OpenRouter's routing rows, and the Context size with Auto-update on connect. Only the fields your provider uses are shown. Under the Test heading, the Connection row runs a test when you press Enter and reads "Connecting", then "Connected" or "Disconnected" with the reason; it clears whenever a setting or the connection's status changes, and a change made while a test runs cancels the test. Every row is explained in Connections.

Samplers

Until a provider is chosen this tab says "Select a provider to set its samplers." After that it shows a Preset row labeled with the protocol, such as "Preset (Text Completions)", then the samplers in groups. Each row's note shows the default as "Default: X" when you have overridden it, the allowed range as "min · max · step", and for the sampler order the list of names it refers to. Values display as they would be sent. A Global bans row sits with the text-completions bans and applies under every text preset. The samplers themselves, their defaults and which providers accept them are in Samplers.

Prompt

Three sections, one for each piece of the prompt you can swap.

  • System prompt. A Preset row that allows None, and a System prompt row that previews the first six lines of the text, or "No system prompt." when it is empty. Enter opens the full editor. When you have edited the text away from the preset, the row is marked and notes "Preset: N characters" or "Preset: None". If the character's card is set to prefer its own system prompt, a note tells you what happens to this one: either "The character's card supplies the system prompt; this one is used only where the card writes {{original}}." or "…; this one is not used." See Card prompts.
  • Context template. A selector with no None, then the template's fields. These fields edit the template itself, not an override, so a change here applies to every chat using that template. The rows list can be reordered with Move up and Move down and each row has an Edit prefix action. Fields that only matter for one protocol say so in their note. What each field does is in Context template.
  • Instruct template. Shown only when the connection uses text completions. A selector and the template's fields, again edited in place. See Instruct template.

Participants

Who is in the chat. Under Persona, a Preset row picks your persona and a Description row shows its text, which you can override for this chat alone. Under Character, the Preset row picks the character, with Description, Prefer the card's system prompt and Prefer the card's post-history instructions below it, each overridable and noting "Preset: X" when overridden. Picking a character seeds its greetings into an empty chat, and choosing the character that is already selected reapplies it. Everything about these two is in Personas and characters.

Lore

The Lore books row holds the chat's own books as an ordered list: Add lore book adds one, and each book has Move up, Move down and Remove. Books attached to the persona and the character join these automatically. The Activation rows below tune how entries fire; what each one means is explained in Lore books.

Moving around and editing rows

Settings and the Library share one layout and one set of keys. The screen is split by a vertical rule: the pane on the left lists the tabs, the pane on the right lists that tab's rows.

← / →
Switch between the two panes.
↑ / ↓
Move between tabs or rows, skipping headings and tabs that do not apply right now (those show muted). If the tab you are on stops applying, the cursor moves up.
PageUp / PageDown
Move a page at a time.
Enter
Change the row. An on/off row flips. A choice opens a list. A long text opens the full-screen editor. A short field edits in place. An action row runs.
Tab
Open the row's actions, such as Save, Rename, Reset or Delete.
Esc
Step back: close an open entry if one is open, otherwise clear a filter if one is typed, otherwise close the screen.
Alt+S, Alt+<, Alt+>
Sort a tab's entries and set the direction, keeping the cursor on the same entry. Used by lore book entries in the Library.

Rows sit in sections with headings. Each row shows its label on the left and its value on the right, cut to fit one line, with ∗ marking an override. The footer shows the keys that apply right now, such as "← →: switch pane", "enter: change, tab: actions" and "esc: back", "esc: clear" or "esc: close", along with the row's help text. A refusal shows there in red instead.

Editing in place

Short fields open an editor beside the label, or below it when the window is narrow. Enter checks the value and saves it, Esc cancels. On a number, ↑ and ↓ step the value. Characters the field cannot take are ignored. A secret such as an API key is masked as you type and saved straight to the account. A paste is converted to fit the field.

  • Numbers step to the next multiple of their step (1 for whole numbers, 0.01 for decimals unless the field says otherwise) and stay within their range, which the note shows as "min X · max Y · step Z". A blank clears an optional number. Pasting into a number is refused, and text that is not a number is refused with "x" is not a number.
  • JSON fields such as extra request fields and logit bias take a JSON value; blank means unset, and bad input is refused with "Invalid JSON: …".
  • One-per-line lists such as banned tokens, quantizations and model providers edit one entry per line.
  • Secrets always open empty, never showing the saved value.

Values display in a compact form: a choice shows its label, a list shows "N entries", "N books", "N scripts" or "None", a checkbox list shows "N of M enabled", a three-way choice shows Default, Yes or No, an on/off row shows [x] or [ ], newlines show as ↵, and anything longer than 80 characters is cut.

Choice lists

A choice opens a list. ↑ and ↓ move, PageUp and PageDown page, Enter chooses and Esc backs out. Choosing the item that is already selected does nothing, with one exception: choosing the current character again reapplies it. The model list and the lore book list are long, so they filter as you type by name or description; Esc clears the filter before it closes the list. The model list starts on the current model, and for providers that accept any model id the list offers "Use what you typed". While a list is loading it says "Loading…"; other things you may see are "Nothing left to add.", "No matches for "x"." and "No models."

Popups

Small questions open over the board, near the cursor. There are four kinds: the actions menu, a titled choice with a line or two of detail, a Keep/Delete confirmation that defaults to Keep, and a one-line text field for names. Name prompts are titled "Save as", "Rename", "New kind" or "Account", and an empty name is refused.

↓ or Tab / ↑
Next and previous item, wrapping around.
Enter
Choose, or submit the name.
Esc
Back out. Backing out of a Delete returns to the actions menu on the same item.
Ctrl+Z, Ctrl+Shift+Z or Ctrl+R
Undo and redo in a text field.

In a text field, Tab and newlines are ignored and pasted newlines become spaces. An error shows in red under the field.

Lists of entries

Some rows hold a list: greetings, example messages, lore books, context template rows, lore entries. Each entry shows as a checkbox and its text. Enter toggles the checkbox; a locked entry, such as a lore row in a context template, has a muted checkbox that cannot change. An add row at the bottom appends a new entry, and a list of names adds from the names not yet used, saying "Nothing left to add." when there are none. Tab on an entry opens its actions: Edit, Duplicate, Move up, Move down, Edit text, Edit prefix, Move to book, Copy to book, Delete (which asks "Delete this entry?" and shows the text) or Remove (which does not ask), whichever apply to that list.

The full-screen text editor

Long texts such as descriptions, system prompts and lore content open a full-screen editor titled by the field.

Enter
Insert a newline.
Ctrl+S
Save and close.
Ctrl+Z, Ctrl+Shift+Z or Ctrl+R
Undo and redo.
Esc
Close at once if nothing changed. Otherwise a question offers Discard and close, Save then close or Cancel.
Home / End, Ctrl+Home / Ctrl+End

A click places the cursor, a drag selects and the wheel scrolls. With text selected, the footer switches to "ctrl+c: copy, ctrl+x: cut, esc: clear".

Filters

Some lists filter as you type: lore entries in the Library, the model list, the lore book list. Any printable character starts the filter, which shows above the list as "🔍 query" only while it has text and scrolls sideways when long. Arrow keys and paging always go to the list, not the filter. Esc clears the filter. A filter has no undo, so Ctrl+Z does nothing there. Switching tabs or opening another box clears it too.

The mouse works everywhere on the board: the wheel scrolls the pane under the pointer, a click moves to a row, and a drag selects text in the full-screen editor. While a popup is open the wheel does nothing.

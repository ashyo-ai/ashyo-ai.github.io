TUI

Run ashyo with no arguments to open the interactive surface. It takes over the terminal's alternate screen, never relies on scrollback, and puts every decision in front of you before it happens.

Starting

$ ashyo
$ ashyo session resume 6f1c2a0e-3b7d-4c1e-9a2f-0d8e5b4c7a11

Without a session id, Ashyo creates a new session in the current directory. The terminal must be at least 24 columns by 12 rows; below that, input is held and a resize notice is shown. The mouse wheel scrolls the pane under the pointer and a click moves focus.

Layout

Top to bottom: the transcript, an interaction pane that docks only when something needs you, the composer, the command completion dock while you are typing a command, and a one-line status line. The interaction pane takes at most 40% of the rows and the transcript always keeps at least five, so a long approval scrolls inside its box rather than pushing the conversation off screen. The composer is exactly as tall as what you have typed, up to five rows: it takes a row from the transcript for each line and gives it back as you delete. Past five rows it stops growing and scrolls to keep the line you are on in view. A line too long for the width counts as the rows it wraps to, the same as lines you ended yourself.

The interaction pane takes focus as it docks, so an approval never sits waiting for you to notice it. Whatever you were typing is left in the composer untouched, and when the pane closes focus goes back where it came from — the composer, or the transcript if that is what you were reading. A question with no options is the exception: it is answered by typing, so it leaves the composer focused.

Every line in the transcript is labeled with who produced it: you, the provider and model that answered, tool: <name> for a call, ashyo for the harness's own reports, and advisor (note), advisor (concern), or advisor (blocker) for the advisor. A note the harness dropped is labeled — dropped: it is shown, and the model never read it. A concern or blocker that advisor.immuneTurns held back is labeled — held: it keeps its kind, interrupts nothing, and reaches the model with your next message. A call a blocker cut short says so where the call is, and a turn the advisor started opens with a line saying so. The transcript is a projection of the branch you are on, so a resume or a branch switch shows the same lines in the same places.

Keys

Enter
Send the composer.
Shift-Enter / Alt-Enter / Ctrl-J
Insert a newline, in the composer and in the argument editor. All three work in every terminal. The one thing a terminal can take away is Shift-Enter itself: telling it apart from Enter needs the keyboard enhancements Ashyo asks for at startup, and a terminal that does not grant them — tmux among them — sends a plain Enter for the chord unless you have bound it to Esc Enter, which arrives as Alt-Enter and writes a newline. F1 says which terminal you are in. Alt-Enter is also the key that answers the interaction pane: focus decides which it is, so it writes a newline while you are in the composer and confirms while the pane has focus. Shift-Enter and Ctrl-J answer nothing there.
Tab / Shift-Tab
Cycle focus: transcript, interaction pane, composer.
PageUp / PageDown
Scroll the focused pane by a page.
Ctrl-Up / Ctrl-Down
Scroll by a line.
g / G
Jump to the top or bottom of the transcript.
/
In an empty composer, open the command completion dock. With the transcript focused, search it; n and N step through matches.
Ctrl-T
Step the reasoning effort up through the active model's levels, wrapping. See Reasoning effort.
Ctrl-S
Open the session picker.
F1
Toggle key help. /keys does the same.
← / →
Move the highlighted option in the interaction pane.
Alt-Enter (interaction focused)
Answer the interaction pane with the highlighted option. Nothing else answers it: Enter and the digit keys do nothing there, because the pane takes focus the moment it docks and a key already on its way to the composer must not be able to allow a tool call. The same chord writes a newline while the composer has focus, and the pane never sees it there.
e
Edit a tool call's arguments before allowing it.
Esc
Close the completion dock, an overlay, or the search; otherwise interrupt the running turn, or cancel a pending login. An Esc that closed the dock has acted: it interrupts nothing and starts no Esc Esc pair.
Esc Esc
Open the session tree, when the first press had nothing to close, interrupt, or cancel. Two presses within half a second.
Ctrl-C Ctrl-C
Quit. Two presses within 150 ms; a single Ctrl-C does nothing at all — it stops no turn, quits nothing, and writes nothing. With no turn running Ashyo leaves at once and the session records a normal exit. With a turn running it asks first: see Quitting. /quit does the same.

Quitting

Quitting an idle conversation needs no confirmation — nothing is lost — so Ctrl-C Ctrl-C and /quit both leave at once, and the session's last line records a normal exit. Quitting while a turn is running throws that turn away, so it asks first.

The question docks where approvals dock, as A turn is running. Quit anyway? [y/N], and takes focus as it opens. The turn keeps running while it waits: the answer keeps streaming into the transcript behind it, and a turn that finishes while the question is up does not dismiss it.

y
Quit. A turn still running is interrupted and the session records an interrupt exit; if it finished while the question was up there was nothing to interrupt, and the exit is a normal one.
n / Esc
Dismiss the question. The turn keeps running, nothing is written, and focus goes back to the pane it came from — including an approval the question was covering, which is untouched and still waiting for you.
everything else
Nothing. Enter above all, because Enter is the key already on its way to the composer when a question appears under it. The question owns every key while it is up, so Tab, F1, and a further Ctrl-C do nothing either.

Either way, leaving is a clean exit: Ashyo settles the turn, writes the session's exit line, drains memory consolidation, and exits 0.

Slash commands

A message beginning with / is a command. It is never sent to the model and never becomes a turn in the log.

CommandEffect
/modelShow the active model, how it was chosen, and the role's configured list.
/model <provider>/<model>Switch this conversation to one model with no fallback. Recorded in the log. Refused while a turn is running.
/thinkingShow the chosen reasoning effort, the level the next request would actually carry, and the levels the active model offers.
/thinking <level>Set the reasoning effort to one of the active model's levels. Recorded, survives later model switches, refused mid-turn. A level the model does not offer is refused with the ones it does. See Reasoning effort.
/titleShow the session title.
/title <text>Rename the session. The picker updates at once.
/planToggle plan mode. See below.
/plan <request>Enter plan mode and send the request as the next turn.

/logout openrouter|openai-codexRemove a credential.
/keysOpen the key help.

Command completion

Type / into an empty composer and a dock opens directly beneath it, listing every command above with its argument and what it does. Each further character keeps the commands whose name starts with what you have typed, so /t leaves /thinking, /title, and /tree. A slash after other text is an ordinary character, and a slash with the transcript focused still starts the transcript search.

↑ / ↓
Move the highlight, scrolling the list when it reaches the edge.
mouse wheel
Scroll the dock. The transcript stays where you left it.
Tab
Complete the highlighted command or argument into the composer.
Enter
Send it. A command that takes no argument, a command whose name you have already typed in full, and a highlighted argument all send on one press; a command you have only started spelling is completed instead, and the dock moves on to its arguments.
Esc
Close the dock and nothing else. What you typed stays in the composer.

Once a command's name is complete and followed by a space — typed, or added by Tab — the dock lists that command's arguments, drawn from the session as it stands: the levels the active model offers for /thinking, the provider names for /login and /logout with --device offered after a provider, and the active role's configured models for /model. Typing narrows them by what appears anywhere in the candidate, so h leaves high and xhigh. /title and /plan take free text nothing can offer, so the dock closes on the space after their name; so does a prefix nothing matches, leaving what you typed in the composer.

The dock shows tui.commandCompletionLimit rows at a time — ten by default — and scrolls the rest behind a scrollbar on its right edge showing where you are in the list. A short terminal shows fewer: the dock takes what is left after the status line, a docked interaction pane, the composer, and the transcript's five-row minimum, and a terminal with nothing left to give opens no dock at all. The dock and a docked approval can be open at once, one below the composer and one above it; closing either leaves the other where it is.

Reasoning effort

Reasoning effort is model-specific. Every model offers an ordered set of levels drawn from none, minimal, low, medium, high, xhigh, max: Ashyo ships the sets for the models it knows, a model it does not know offers low, medium, high, and a config entry can declare or replace a set with reasoningEfforts.

Ctrl-T steps the effort one level up the active model's set and wraps past the strongest back to the weakest, recording and refusing exactly as /thinking does. It starts from the level in effect, and from nothing at all it takes the weakest level above none. On a model with no reasoning control it says so and records nothing.

/thinking accepts only a level the active model offers, and what it records is that choice. What a request carries is the choice mapped into the set of whichever model runs: the nearest level that model offers, and on a tie the weaker one, so a mapping never spends more than you asked for. The same mapping applies to a fallback model that takes a turn after the first one fails.

So a chosen xhigh on a model whose levels stop at high sends high and the status line reads thinking:high (xhigh); switching back to a model that offers xhigh sends xhigh again, with nothing new recorded. A model declared with no reasoning control is sent no effort at all, shows no thinking field, and answers /thinking by saying so.

Approvals

When a tool call matches an ask rule, or no rule at all, the interaction pane docks with the tool name, the full arguments, the rule that matched, the mode and profile, and anything your before-hooks said about the call. Nothing is truncated; the pane scrolls.

There are two answers, Allow and Deny. Each covers the one call in front of you, and neither writes a rule. If you want the decision to stick, put it in the config file; it applies on the next call without a restart.

The pane takes focus as it docks and opens with Deny highlighted. ← and → move the highlight and Alt-Enter confirms it. Alt-Enter is a newline chord in the composer, and this is the other half of that: while the pane has focus the chord is the pane's. A Shift-Enter your terminal sends as a key of its own does nothing here — the pane has no binding for it — but one your terminal is configured to send as Esc Enter, as Alacritty is above, arrives as Alt-Enter and confirms, exactly as a real Alt-Enter does. So a chord of that kind still in flight when an approval docks answers with the highlighted option, which is why the highlight opens on the safe one. Enter and the digit keys answer nothing at all: the key you were about to press to send a message must never be the key that allows a call you have not read.

Press e to load the arguments into the composer as JSON. Enter sends the edited call as an Allow; Esc returns to the prompt. JSON that does not parse is refused in place and your text is kept. The log records the call the model intended, the call you approved, and the call that ran, as three separate fields. An edit to an agent call may narrow the child's access but never widen it.

Plan mode

/plan switches the current conversation, on the current branch, to the plan role and a read-only profile: shell is unavailable, and edit and write work only beneath the session's scratch directory. The model is told to investigate without changing the working tree and to write a decision-complete plan to plan.md in that scratch directory. The status line shows the path and whether the file exists yet.

When a turn ends and plan.md is non-empty, a review docks with three choices: approve and execute, refine, and stop planning. It takes focus and opens on the first of them, and Alt-Enter answers it. Approving records the plan and its SHA-256 in the log as an immutable event, switches back to the normal profile, and sends the plan as the next user turn with the instruction to execute it exactly as written. Nothing forks: the plan and its execution are one branch.

Plan mode needs a configured plan role and cannot be toggled while a turn is running.

Overlays

Session tree

/tree, or two Esc presses with nothing to close or interrupt, draws the branch structure of the current session, roots first. ● marks the current leaf, ○ a node you can switch to. Enter switches; the transcript re-projects onto the chosen path. Send a message from an earlier node and you have a new branch; the old one is untouched and both survive a restart. See Sessions.

Session picker

Ctrl-S lists sessions created in this project directory. Tab widens to every session and back. Rows show the title, or the id for an untitled session, and mark empty sessions. Opening a session from another project is allowed; the workspace follows the session.

Settings

/settings covers the whole terminal with one box: the categories on the left, the selected category's rows on the right, two rows describing the highlighted row below them, and the keys you have across the bottom. ← and → move between the two lists, ↑ and ↓ move within the one that has the highlight and scroll it at the edges, and the wheel scrolls whichever list the pointer is over. Moving to another category puts the highlight on its first row. Esc closes it and gives back the transcript, the composer, and the status line exactly as they were.

It is a placeholder for now. The categories are Appearance and Model, the rows under them are inert, and nothing on the screen writes anything: every setting still lives in the config files.

Keys

F1 lists every binding. Overlays close with Esc or q, and the picker and this help also close with the key that opened them; the settings screen closes with Esc alone, because its rows are to take typed text and q is a character.

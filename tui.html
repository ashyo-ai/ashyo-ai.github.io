TUI

Run ashyo with no arguments to open the interactive surface. It takes over the terminal's alternate screen, never relies on scrollback, and puts every decision in front of you before it happens.

Starting

$ ashyo
$ ashyo session resume 6f1c2a0e-3b7d-4c1e-9a2f-0d8e5b4c7a11

Without a session id, Ashyo creates a new session in the current directory. The terminal must be at least 24 columns by 12 rows; below that, input is held and a resize notice is shown. The mouse wheel scrolls the pane under the pointer and a click moves focus.

Layout

Top to bottom: the transcript, an interaction pane that docks only when something needs you, the composer, and a one-line status line. The interaction pane takes at most 40% of the rows and the transcript always keeps at least five, so a long approval scrolls inside its box rather than pushing the conversation off screen. The composer grows to five rows.

Every line in the transcript is labeled with who produced it: you, the provider and model that answered, tool: <name> for a call, ashyo for the harness's own reports, and advisor (note), advisor (concern), or advisor (blocker) for the advisor. A note the harness dropped is labeled — dropped: it is shown, and the model never read it. A concern or blocker that advisor.immuneTurns held back is labeled — held: it keeps its kind, interrupts nothing, and reaches the model with your next message. A call a blocker cut short says so where the call is, and a turn the advisor started opens with a line saying so. The transcript is a projection of the branch you are on, so a resume or a branch switch shows the same lines in the same places.

Slash commands

A message beginning with / is a command. It is never sent to the model and never becomes a turn in the log.

CommandEffect
/modelShow the active model, how it was chosen, and the role's configured list.
/model <provider>/<model>Switch this conversation to one model with no fallback. Recorded in the log. Refused while a turn is running.
/thinkingShow the reasoning effort and where it came from.
/thinking low|medium|highSet the reasoning effort. Recorded, survives later model switches, refused mid-turn.

/plan <request>Enter plan mode and send the request as the next turn.
/login openrouter|openai-codex [--device]Log in without leaving the session. Esc cancels.
/logout openrouter|openai-codexRemove a credential.
/keysOpen the key help.

Approvals

When a tool call matches an ask rule, or no rule at all, the interaction pane docks with the tool name, the full arguments, the rule that matched, the mode and profile, and anything your before-hooks said about the call. Nothing is truncated; the pane scrolls.

There are two answers, allow once and deny once. Neither writes a rule. If you want the decision to stick, put it in the config file; it applies on the next call without a restart.

Press e to load the arguments into the composer as JSON. Enter sends the edited call as an allow-once; Esc returns to the prompt. JSON that does not parse is refused in place and your text is kept. The log records the call the model intended, the call you approved, and the call that ran, as three separate fields. An edit to an agent call may narrow the child's access but never widen it.

Plan mode

/plan switches the current conversation, on the current branch, to the plan role and a read-only profile: shell is unavailable, and edit and write work only beneath the session's scratch directory. The model is told to investigate without changing the working tree and to write a decision-complete plan to plan.md in that scratch directory. The status line shows the path and whether the file exists yet.

When a turn ends and plan.md is non-empty, a review docks with three choices: approve and execute, refine, and stop planning. Approving records the plan and its SHA-256 in the log as an immutable event, switches back to the normal profile, and sends the plan as the next user turn with the instruction to execute it exactly as written. Nothing forks: the plan and its execution are one branch.

Plan mode needs a configured plan role and cannot be toggled while a turn is running.

Overlays

Session tree

Ctrl-T draws the branch structure of the current session, roots first. ● marks the current leaf, ○ a node you can switch to. Enter switches; the transcript re-projects onto the chosen path. Send a message from an earlier node and you have a new branch; the old one is untouched and both survive a restart. See Sessions.

Session picker

Ctrl-S lists sessions created in this project directory. Tab widens to every session and back. Rows show the title, or the id for an untitled session, and mark empty sessions. Opening a session from another project is allowed; the workspace follows the session.

Keys

F1 lists every binding. Any overlay closes with Esc, q, or the key that opened it.

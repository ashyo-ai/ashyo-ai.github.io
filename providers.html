Providers

Ashyo talks to exactly two providers: OpenAI Codex over OAuth, and OpenRouter with an API key. Models are named provider/model, and both providers are driven through the same stateless request shape, so a session can move between them without being rewritten.

Model references

Every model reference is openai-codex/<model> or openrouter/<model>. Anything else is rejected when the config is decoded. OpenRouter ids contain their own slashes, so openrouter/~z-ai/glm-flash-latest is the provider segment followed by the OpenRouter id as OpenRouter spells it.

Credentials

Credentials live in $XDG_DATA_HOME/ashyo/auth.json, default ~/.local/share/ashyo/auth.json, apart from configuration so the config file can be shared. The file must be a regular file, not a symlink, with mode 0600; anything looser is refused with an error naming the permissions. Absent providers are omitted from the file.

Ashyo reads no API key from the environment. The sidecar is the only source.

OpenAI Codex

$ ashyo login openai-codex

The browser flow opens your default browser with xdg-open and listens for the callback on localhost:1455, falling back to port 1457 if that is taken. If the browser cannot be launched, Ashyo prints the URL to open by hand and keeps waiting. Interrupt with Ctrl-C if this machine has no browser at all and use the device flow instead:

$ ashyo login --device openai-codex
Open https://auth.openai.com/codex/device and enter code XXXX-XXXX

Tokens are refreshed before they expire and the file is rewritten atomically. Logging out revokes the token with OpenAI and removes the entry.

OpenRouter

$ ashyo login openrouter
OpenRouter API key:

The key is read from the terminal with echo off and saved. --device has no meaning here and is reported as such. Logging out removes the entry; nothing is revoked remotely.

From inside the TUI

/login and /logout take the same arguments and run without leaving the session. A pending login waits for the browser or device code; press Esc to cancel it. One credential command runs at a time.

Fallback and retries

A role lists models in order. When the first model's request fails before any output has streamed, the next entry is tried:

  • A retryable status is retried at most twice before the stream starts. A Retry-After header of up to 30 seconds is honored; a longer one makes that model terminal for the turn without sleeping.
  • A 404 advances to the next entry immediately.
  • Once output has started streaming, a failure ends the turn. There is no mid-stream retry or fallback, so you never get a spliced answer.
  • --model and /model select one model with no fallback list.

Stateless replay

Every request carries the whole conversation. Ashyo sends store: false and never uses a server-side previous response id, so nothing about your session lives on the provider. Each completed output item is written to the session log exactly as received, tagged with the provider that produced it. When a later turn goes to a different provider, items from the other provider are projected into a shape it accepts: reasoning, provider ids, and encrypted content are dropped, and tool call pairs are rebuilt. The log itself is never rewritten. Switch back and the original items replay verbatim, including Codex encrypted reasoning.

The transcript labels each turn with the provider and model that produced it, so a session that crossed providers still reads honestly.

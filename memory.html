Memory

Ashyo keeps long-term memory in a local SQLite database with embeddings computed on your machine. The model can recall, retain, reflect, and edit; the harness consolidates each turn in the background.

Database

The store is memory.dbPath, default ~/.local/share/ashyo/memories.db. It is a SQLite file in WAL mode with full-text indexes and a table of vectors. The file carries an application id of 1095977049; a database with any other id is refused before anything is written, so pointing dbPath at some other tool's database is an error, not a migration.

Embeddings

Text is turned into 384-dimensional vectors by BAAI/bge-small-en-v1.5, run by an ONNX interpreter built into Ashyo. There is no ONNX Runtime, no Python, no sidecar, and no network call at query time. The model files are downloaded once from Hugging Face into ~/.local/share/ashyo/models/BAAI_bge-small-en-v1.5/ on first start; the download is retried five times and can take several minutes.

If the model cannot be downloaded or loaded, Ashyo still starts. Recall runs on full-text search only and a notice in the transcript says so. When the embedding model changes, memories written under the old one are re-embedded in the background and a startup notice reports it; until that finishes, recall results carry a warning.

Banks

Memories are grouped into banks. The default bank is shared across everything. Each project gets its own bank named from the directory's basename and a hash of its absolute path, so two projects with the same name do not collide. The recall, reflect, and retain tools take an optional bank and project.

Kinds

KindMeaning
workingShort-lived. Eligible for consolidation after 12 hours, expires after 24.
episodicWhat happened: a consolidated account of a turn, or a retained note.
factA durable statement extracted from an episode. Fact ids are read-only.

Tools

recall

Hybrid search: full-text and vector similarity, ranked together with recency and confidence. Returns up to 40 memories with their content previewed to 500 characters and a truncated flag with the full length. A warnings list names any degradation: the query could not be embedded, some vectors came from another model, or re-embedding is in progress.

retain

Stores one or more facts with optional context. A stored memory whose embedding failed is a success with a warning, not a failure; it is found by full-text search until it is re-embedded.

reflect

Recalls, then asks the memory role to synthesize an answer from what it found. Without roles.memory the tool reports itself unavailable and names the key. With nothing relevant it says so rather than inventing.

memory_edit

update rewrites a memory's content or importance, reading the full row first so a concurrent change is not lost, and re-embeds what changed. forget deletes. invalidate marks a memory superseded by replacement_id. The reply is memory_<op>: <id>.

Consolidation

When roles.memory is configured, every completed turn is queued for a background worker that asks that model for one JSON object: an episode, facts, gists, graph edges, triples, and annotations. The episode and facts are stored and embedded. The role is a list like any other, so an entry that fails before it answers hands the extraction to the next one. Without the role, print mode stores the exchange as a plain episode.

The queue is drained before Ashyo exits, and the embedding model is released only after that. A drain that degraded, because an embedding failed, is a warning on stderr and exit 0; a store failure is exit 5.

Inspecting

$ ashyo memory inspect <memory-id>

Prints the record as JSON. Ids appear in recall results.

Agents

Ashyo gives each job its own model list, called a role, and lets the main conversation delegate to subagents that work in their own git worktree. An optional advisor watches the conversation and speaks to the model, but never acts.

Roles

RoleUsed for
defaultThe main conversation. Required.
planPlan mode.
taskSubagents.
advisorThe second opinion described below.
smol, tinyUtility work: memory consolidation and reflect. smol is preferred when both exist.
visionThe image tool.

Each role is a list; the first model is tried first and the rest are fallbacks. See Config.

Advisor

Configure roles.advisor and a second model follows the main session: your submissions, completed model turns, tool and policy results, and subagent results are summarized to it as they become durable. It has no tools, and nothing it says is executed. Everything it says is recorded in the session as an advisor event and rendered in the transcript where it landed, and the main model reads it too, as a message marked as the advisor's rather than as yours.

Note, concern, blocker

Each update the advisor is shown carries a short label, and everything it says names one of those labels and one of three kinds. The kind decides when the main model reads it.

KindReaches the model
noteWith your next message, ahead of it. It never touches a turn already running.
concernBetween two steps of the turn it is about — after the current tool results, before the next model call. Nothing running is cancelled.
blockerAt once. If it flags the model output whose tool calls are still running, the running call is cancelled and the rest are skipped, and the model answers the blocker in the same turn. If that turn has already finished, the blocker starts a new one, which you stop with Esc like any other.

A note that names no label, or repeats a note the model has already read, is shown in the transcript marked dropped and never delivered. A tool call the advisor tried to make is a violation: recorded, shown, never executed, and never delivered. The status line shows the advisor's state and its token usage.

A blocker that cut a turn short leaves its mark in the transcript: the call it interrupted and the calls it skipped both say so, and a turn the advisor started says who started it. Nothing the advisor said is lost to Esc — anything it had not yet delivered goes out with your next message, and a blocker arriving just after you pressed Esc starts nothing.

By default the advisor carries everything it has seen since the conversation was opened into every request, so it costs more the longer the session runs. Set advisor.lookBack to a count of its own recent turns to cap that, and advisor.enable to false to turn the advisor off without losing the model list; see Config.

The advisor answers in the background and your turns do not wait for it, so on a fast conversation its notes can arrive a turn or two late. Set advisor.syncTurns to the number of turns it may fall behind and a turn pauses at its start until it catches up, for at most 30 seconds; see Config.

Once the advisor has cut in — a concern delivered mid-turn, a blocker that cancelled calls, or a blocker that started a turn — it is held to turn boundaries for a while, so the model gets to finish what it is doing. advisor.immuneTurns is how many turns that lasts, three by default; a concern or blocker held this way is shown in the transcript marked held and goes out with your next message. Set it to 0 to let the advisor cut in every time; see Config.

The advisor is a second opinion, not a second driver: it can steer the model and stop it, and it can never run anything.

Subagents

The agent tool lets the model delegate. It needs roles.task; without it the tool reports that the role is not configured.

ActionDoes
createStart a child with a prompt and an access level. Returns the agent id, status, access, and the child's session id.
waitBlock until the child finishes and return its result.
inspectReport the child's status.
cleanupRemove the child's worktree and metadata. Refused for dirty or unintegrated work unless abandon is set.

Read-only and mutable

  • A read-only child shares the parent's working directory. shell is denied outright and edit and write are denied everywhere. It can read, search, fetch, and use memory.
  • A mutable child gets its own git worktree on its own branch, placed at the same repository-relative directory the parent was in. Its writable root is that worktree and nothing else. When it finishes, its branch is left committed and clean for you or the parent to integrate with ordinary git.

A mutable child needs a clean parent: a checked-out branch with no uncommitted changes. Otherwise creation is refused with mutable_agent_requires_clean_git and no branch or worktree is made. A read-only parent, including one in plan mode, cannot spawn a mutable child.

What crosses back

A child's session is its own log with its own tool calls, model events, and reasoning. None of it enters the parent's context. What the parent receives is a compact result: a summary, the branch name, the base and head commits, a validation status, and the child's status. A grandchild is contained in the same way at its own level, so each level of delegation sees only the summaries of the level below.

The rules that decide a child's calls are the same live rules as the parent's, and an interactive approval that edits an agent call can narrow the child's access but never widen it.

Steering

steer sends a message to a running child, queued on the child's branch, or to the parent when target is empty or parent. A steer to a preserved dirty child restarts it.

Statuses

A child reports running, finishing, clean, policy_error, interrupted, failed, cleaning, or cleaned_up. Worktrees themselves are tracked as creating, ready, failed, orphaned, dirty_child, clean, removed, or abandoned, and ashyo diagnostics counts them.

Cleanup

Worktrees are not removed automatically. Once a child's branch is merged, clean it up from the model with agent cleanup or from the shell:

$ ashyo agent cleanup <agent-id>
$ ashyo agent cleanup <agent-id> --abandon

A child with uncommitted changes is always refused. A child whose branch was never integrated is refused unless you pass --abandon, which discards it. Metadata for each worktree lives under ~/.local/share/ashyo/worktrees/.

Welcome to Ashyo

Ashyo is a terminal app for roleplaying and chatting with language models. You bring a model, whether that is a server running on your own machine or a hosted account, and Ashyo gives you characters, personas, lore books, swipes, branching chats and full control over the prompt. Everything lives in your terminal and everything is saved on your disk.

What Ashyo is

If you have used SillyTavern, you already know the shape of it: pick a character, pick who you are, start a chat, and shape what the model sees with lore books, templates and samplers. Ashyo brings that way of working to a terminal window, with no browser and no server of its own to run.

  • Characters and personas. Import character cards you already have, or write your own. Your persona is who the model talks to. See Personas and characters.
  • Lore books. Facts that enter the prompt only when the conversation touches them, with keys, recursion, timed effects and a budget so they never crowd out the chat. See Lore books.
  • Swipes and branches. Every reply can have alternatives, and every chat is a tree you can walk, label and fork. Nothing you generate is ever lost. See Swipes and branches.
  • The prompt is yours. System prompts, context templates, instruct templates, samplers and regex scripts are all presets you can switch per chat. A built-in inspector shows you the exact prompt before it leaves. See Prompt building and Context and budget.
  • Your files stay with you. Chats are single files on your disk, settings are one JSON file, and nothing is sent anywhere except to the model you chose. See Files and logs.
  • It speaks SillyTavern. Character cards, World Info books, instruct and sampler presets and chat logs from SillyTavern all import, and chats export back out. See Import and export.

What you need

  • A Linux machine on x86_64 and a terminal window at least 24 columns by 12 rows. Ashyo uses the mouse when your terminal offers it, but every action has a key.
  • A model to talk to. Ashyo connects to KoboldCPP or llama.cpp running on your own machine, to any OpenAI-compatible server, to OpenRouter with an API key, or to a ChatGPT subscription through OpenAI Codex. See Connections.
  • Optional helpers: a clipboard tool such as wl-paste, xclip or xsel for pasting with Ctrl+V (copying needs nothing, it works over the terminal itself, even through SSH), notify-send for a desktop notification when a reply arrives, and xdg-open so the Codex login can open your browser.

Install

Ashyo is built from source with the Rust toolchain. The build targets static musl, so the result is one file that runs on any x86_64 Linux machine with nothing else installed. You need rustup with the musl target added, plus the musl-gcc wrapper from your distribution's musl package.

$ rustup target add x86_64-unknown-linux-musl
$ git clone https://github.com/ashyo-ai/ashyo
$ cd ashyo
$ cargo build --release

The binary lands at target/x86_64-unknown-linux-musl/release/ashyo. Copy it somewhere on your PATH and check it runs:

$ ashyo --version
ashyo 0.1.0 (34c12462)

That is the only command line option. Anything else, --help included, is refused with "ashyo: unknown option". Everything happens inside the app.

First run: connect a model

Start Ashyo with no arguments. Because there is no configuration yet, it opens Settings on the Connection tab and tells you to "Set up a connection to start chatting." The rows you fill in here become the defaults for every new chat.

$ ashyo
  1. Move to Provider and press Enter. Pick the kind of server or service you are using. KoboldCPP is the default.
  2. Fill in how to reach it. Local servers want an Address and Port (KoboldCPP defaults to 127.0.0.1:5001, llama.cpp to 127.0.0.1:8080). An OpenAI-compatible server wants a Base URL. OpenRouter and Codex need nothing here.
  3. If the service needs credentials, pick an Account and either paste your API key (OpenRouter and OpenAI-compatible) or run Login (Codex). Local servers skip this.
  4. Choose a Model where the provider has one. Ashyo lists what the server offers. KoboldCPP has no model row at all, since it serves whatever it has loaded, and llama.cpp uses its loaded model when you leave the row empty.
  5. Press Enter on the Connection row under Test. It reads "Connecting", then "Connected", or "Disconnected" with the reason.

Press Esc to leave Settings. You land in the chat picker, which is empty for now. The details of every provider, including the two protocols and what context size means, are in Connections.

Tip

You can come back to Settings any time with /settings. With a chat open, the Settings screen edits that chat; with no chat open it edits the defaults new chats start from. See Settings and presets.

Your first chat

Press Esc to close the empty picker, type /new in the composer and press Enter. A fresh chat opens with the built-in persona User and the built-in character Assistant. Type a message and press Enter to send it. The reply streams in under your message, and while it does the line above the composer shows a spinner and how long it has been generating.

A few things to try straight away:

  • Press ← or → on an empty composer to swipe the last reply. → past the last swipe generates a new one.
  • Press Esc while a reply is generating to stop it. Whatever arrived so far is kept.
  • Press Ctrl+↑ to move into the transcript, then ↑ and ↓ to mark a message and Tab for its actions: edit, delete, copy, continue, and more.
  • Type / at the start of the composer to see every command with a one-line description. The list narrows as you type.
  • Press Ctrl+S to open the chat picker, and /rename My first chat to give the chat a name.

To give the model a character to play, open the Library with /library and import a character card, then pick it on the Participants tab of Settings. The chat's greeting appears at once. When you are done, /quit saves everything and leaves.

Where things live

Ashyo follows the XDG base directories. The paths below are the defaults when XDG_CONFIG_HOME and XDG_DATA_HOME are unset.

WhatPath
Settings and library~/.config/ashyo/ashyo.json
Chats, one file each~/.local/share/ashyo/chats/
Accounts and keys~/.local/share/ashyo/auth.json
Input history~/.local/share/ashyo/history.jsonl
Log file~/.local/share/ashyo/ashyo.log

More about each file, including what is safe to edit by hand, in Files and logs.

What Ashyo leaves out

A few things are decisions rather than gaps. Ashyo has no image generation, no text-to-speech and no browser interface. Today a chat is one persona and one character. Keybindings are fixed; there is no keymap to configure, which is why this site has a Keyboard reference. Only one copy runs at a time: a second start is refused with "Another copy of Ashyo is already running."

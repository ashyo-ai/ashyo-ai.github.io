Intro

Ashyo is a terminal coding harness for OpenAI Codex and OpenRouter models. It is one Linux binary with no plugins, no MCP, and no sidecar processes. You watch it work, approve what it does, and every conversation is an append-only log you can branch, replay, and resume.

Overview

Ashyo runs a model against your working tree through a fixed set of tools. What separates it from a chat window is oversight:

  • Sessions are logs. Each conversation is one JSONL file. Events are never rewritten, so you can branch from any earlier turn and both branches survive a restart. See Sessions.
  • Policy is the sandbox. Every tool call is decided by allow, ask, or deny rules you write, and an interactive approval shows you the exact arguments before anything runs. Hooks can veto or annotate, never widen. See Permissions and Hooks.
  • Models are roles. The main conversation, planning, subagents, an advisor that watches and can stop the model, and small utility models each get their own model list with fallbacks. See Agents.
  • Memory is local. Facts and episodes go into a SQLite database with embeddings computed on your machine. See Memory.
  • Print mode shares the runtime. ashyo -p runs one prompt uninterrupted with the same policy, tools, and memory as the TUI. See CLI.

Prerequisites

  • Go 1.27 and a C toolchain. The SQLite driver uses cgo.
  • bash for the shell tool, git for mutable subagents, and xdg-open for browser login.
  • An OpenAI Codex account, an OpenRouter API key, or both.

Install

The Go module lives under src/, so build from the project root with go -C src. The output path is relative to src/, which puts the binary in bin/ at the root. The SQLite build tags are required; without them the session index and the memory store fail to open.

$ go -C src build -tags "sqlite_fts5 sqlite_omit_load_extension" -o ../bin/ashyo ./cmd/ashyo

Put bin/ashyo somewhere on your PATH. There is nothing else to install: no runtime, no model server, no background daemon.

Authenticate

Credentials live in one sidecar file, separate from configuration. Log in to whichever providers you use.

$ ashyo login openai-codex
$ ashyo login openrouter

Codex opens a browser for OAuth, or pass --device to get a code you can enter from another machine. OpenRouter prompts for an API key with echo off. Details in Providers.

Configure

Create ~/.config/ashyo/config.json. The only required part is a default role with at least one model. Everything else has a default. With no permission rules every tool call asks you first, so a few allows for read-only tools keep the prompts meaningful.

~/.config/ashyo/config.json
{
  "roles": {
    "default": [
      { "model": "openai-codex/gpt-5.6-luna", "reasoningEffort": "medium" },
      { "model": "openrouter/~z-ai/glm-flash-latest" }
    ]
  },
  "permissions": [
    { "action": "allow", "tool": "read" },
    { "action": "allow", "tool": "grep" },
    { "action": "allow", "tool": "glob" }
  ]
}

A project can add its own .ashyo/config.json in the working directory. Project roles replace global roles of the same name; project rules are consulted before global rules. Both files are watched, and a saved change applies within a second. See Config.

First run

Start Ashyo in a project directory.

$ cd ~/code/myproject
$ ashyo

The first start downloads the embedding model BAAI/bge-small-en-v1.5 into ~/.local/share/ashyo/models/. This happens once and can take several minutes. If the download fails, Ashyo still starts; memory recall falls back to full-text search and the transcript says so.

Type a prompt and press Enter. When the model wants to run a tool that your rules do not already allow, an approval pane docks above the composer showing the tool, its arguments, and the rule that matched. Choose Allow, Deny, or press e to edit the arguments first. Press F1 for every key. See TUI.

Print mode

For scripts and one-off questions, run a single prompt without the TUI. The answer goes to stdout; notices go to stderr.

$ ashyo -p 'Summarize what internal/session does'
$ ashyo -p --model openrouter/~z-ai/glm-flash-latest 'Reply with exactly OK'

Print mode never prompts. Rules that would ask are treated as allow, so give it a rule set you trust. Exit codes distinguish policy denial, provider failure, and interruption. See CLI.

Where things live

Ashyo follows the XDG base directories. The defaults below apply when the variables are unset.

WhatPath
Global config~/.config/ashyo/config.json
Project config<project>/.ashyo/config.json
Credentials~/.local/share/ashyo/auth.json
Sessions~/.local/share/ashyo/sessions/
Memory database~/.local/share/ashyo/memories.db
Embedding model~/.local/share/ashyo/models/
Subagent worktree metadata~/.local/share/ashyo/worktrees/
Log file~/.local/state/ashyo/ashyo.log

What Ashyo leaves out

These are decisions, not gaps. Ashyo has no plugin system, no MCP or ACP server, no LSP or DAP integration, no remote session sharing, no alternate shells, and no pluggable memory backend. The tool registry is fixed. Sandboxing is policy only: filesystem snapshots, network controls, and wrappers stay under your control outside the harness.

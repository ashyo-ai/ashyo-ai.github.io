Troubleshooting

When something goes wrong, Ashyo tells you in a sentence: in red on the notice line above the composer, as a red "error: …" note in the transcript, or on the terminal before it exits. This page collects those sentences by the situation you are in, says what each one means, and what to do about it.

Ashyo will not start

A problem before the screen opens prints one line to the terminal starting with "ashyo: " and exits with status 1. When several things went wrong in a row, the causes follow one another after "; caused by: ".

MessageMeaningWhat to do
"Another copy of Ashyo is already running."Only one Ashyo may use the config and data folders at a time.Switch to the copy that is open, or quit it. A copy that crashed releases the lock as soon as its process is gone.
"ashyo: unknown option …"The only option is --version; anything else is refused, --help included. Exits with status 2.Start Ashyo with no arguments.
"neither XDG_CONFIG_HOME nor HOME is set" or "neither XDG_DATA_HOME nor HOME is set"Ashyo cannot work out where your files live.Make sure HOME is set in the environment you launch from. A relative XDG path is ignored.
"config file …: …", "config file is not valid JSON: …", "invalid value for config field at …", "missing required config key at …", "duplicate config name … at …", "duplicate lore entry uid … at …", "unknown config key at …"The settings file could not be read. Each message names the JSON path of the problem.Fix the file by hand at the path named, or move it aside to start from defaults. Ashyo never repairs or rewrites a file it cannot read. See the config file.
"No {kind} is named …"A persona or character lists a lore book or regex script that does not exist.Edit the list in the file, or add an item with that name.
"…/auth.json: the credentials file must be a regular file, not a symlink" or "…: permissions NNNN expose credentials; require 0600"Ashyo refuses credentials other people on the machine could read.Run chmod 600 on the file, or replace a symlink with the real file. See auth.json.
"…/ashyo.log: …"The log file could not be opened, and logging is not off.Fix the folder's permissions or free disk space. With Log level set to off, Ashyo starts without the file.
A red "Terminal too small" in the middle of the screenThe window is under 24 columns by 12 rows; input is held until it grows.Enlarge the terminal or shrink its font.

On the very first start there is no config file, so Settings opens on the Connection tab with "Set up a connection to start chatting." That is not an error; see First run. Ashyo also quits gracefully and saves every chat on SIGHUP and SIGTERM, so closing the terminal window loses nothing.

Cannot reach the model

Connection trouble shows on the Connection row of the Settings' Connection tab as "Disconnected — " and a reason, and on a failed send as a note. The address in each message is the host and port Ashyo tried.

MessageMeaningWhat to do
"… is not accepting connections (connection refused). Is the server running?"Something answered at the address, but nothing is listening on that port.Start KoboldCPP or llama.cpp, or check the Port. Ashyo keeps probing and reconnects on its own once the server is up.
"… did not accept a connection within N seconds"No answer at all within the connect timeout.Check the Address and any firewall. Raise connect_timeout in the config file for slow networks, see Timeouts and proxies.
"cannot resolve host …", "host unreachable", "no answer", "Disconnected — not yet checked"The name does not resolve, the network cannot route to it, nothing replied, or the connection has not been tried yet.Check the spelling of the host, your network, and press Enter on the Connection row to test.
"HTTP request timed out." or "no data for N seconds; the request was aborted"The server accepted the request but sent nothing for the whole read timeout.A big local model may need longer before its first token: raise read_timeout in the config file.
"Invalid URL …", "Not a valid URL.", "Base URL is required."The OpenAI-compatible Base URL is missing or malformed.Give a full address starting with http:// or https:// and naming a host.
"Choose a connection provider first."The chat has no provider, so there is nothing to send to.Pick one under Route on the Connection tab.
"API key is required."OpenRouter needs a key and the chosen account holds none.Add an account with your key, see Accounts and credentials.
"OpenAI Codex is not logged in; log in from the connection settings' Login row.", "… has no login.", "… has no account named …"The chat names an account that is logged out, missing, or has been deleted.Choose an account on the Account row and run Login.
"The credential changed while it was being replaced."Two changes to the same account crossed.Try again.
"Model listing failed.", "Model provider listing failed.", "Model detection failed.", "Context window detection failed.", "Token count failed.", "Abort failed."A background request to the server failed; these appear as notes and most are harmless.Check the connection. A failed token count only means Ashyo estimates instead; a failed abort only means the server finishes a stopped reply on its own.
"Model picker is not available for provider …"KoboldCPP has no model list to show.Nothing; it serves the model it loaded.
"{provider} answered {status} with no readable error."The server returned an HTTP error without a message Ashyo could show.Look at the server's own log, and at the log viewer for the status.

Logging in to Codex

MessageMeaningWhat to do
"Open this URL to log in: …"No browser could be opened automatically.Copy the address into any browser; the login still completes.
"Listening for the login's callback failed: …"Neither local port 1455 nor 1457 was free for the browser to call back on.Free the port, or use Log in with a device code instead.
"Login cancelled."You chose Cancel login, or the browser page was cancelled.Start again when ready.
"… failed at …: HTTP …"One step of the login was refused by OpenAI's servers.Retry; if it persists, check that the subscription is active.
"The device login timed out after 15 minutes."The code was not entered in time.Run the device login again for a fresh code.
"The login was replaced twice while it was being refreshed … log in again."Another Ashyo or tool rewrote the login while this one was refreshing it.Log out and log in once more.
"… The account is logged out regardless."Revoking the login with OpenAI failed, but it was removed locally.Nothing further; you are logged out.

A reply fails or will not start

While waiting, the streaming card says "Waiting for model… (Ns)" after 3 seconds, "Still waiting for first response… (Ns)" from 8 and "Provider is taking unusually long… (Ns)" from 30. That is patience, not failure; press Esc if you would rather stop. A stopped reply keeps whatever text had arrived, and a reply that produced nothing is discarded without a trace.

MessageMeaningWhat to do
"error: …" as a red note after your messageThe generation failed; the note carries the provider's reason or one of the sentences on this page.Read the reason, then swipe with → or send again. A desktop notification "Generation failed in <chat>: <reason>" is sent if Reply alert is on.
"The response was cut off."The server closed the stream mid-reply.Check the server; what arrived is kept.
"The response was not valid text." or "Failed to decode JSON: …"The server sent something Ashyo could not read.Make sure the Base URL points at an OpenAI-style API and not a web page.
"HTTP transport error: …"The network connection broke.Retry once the network is back.
"The request was cancelled."You stopped it, or the chat closed.Nothing.
"Streaming in progress." or "Cannot close chat while streaming is in progress."The chat is busy generating.Wait, or press Esc to stop the reply first.
"The chat is still loading.", "Chat is still opening.", "Chat is still saving."A long chat is still being read or written.Wait for the notice line's "loading …" to clear; the command you typed stays in the composer.
"no chat is open; press ctrl+s to pick a chat" or "the chat is still opening"You pressed Enter with nothing to send to.Press Ctrl+S and open a chat, or type /new.
"Continuing a message requires a text-completions connection.", "Only the newest message can be continued.", "Only a model message can be continued.", "There is nothing to continue."Continue only extends the newest, non-empty reply, and only over Text Completions.Switch the Protocol, or swipe instead. See Continue.
"This turn holds the most swipes it can."A turn has reached 65,535 swipes.Delete a swipe from the actions menu.
"Only a model message has reasoning."Reasoning can be edited only on replies.Nothing.
"Chat not found." or "Chat not loaded."The chat was closed or deleted out from under the action.Reopen it from the picker.
"The … panicked."A background task crashed. Ashyo keeps running.Retry the action and check the log viewer; the log has the details.

The prompt does not fit

MessageMeaningWhat to do
"The provider's context window is unknown and could not be retrieved. Test the connection or set a context size."Ashyo needs to know the model's window to plan the prompt, and the provider did not say.Press Enter on the Connection row to test, or type a Context size on the Connection tab. See Context size.
"The prompt does not fit the context budget: X tokens against the Y that fit. The system prompt and the last user message are never evicted, so raise the context size, lower the generation reserve, or shorten them."Even with every old message and example dropped, the fixed parts of the prompt plus your message are bigger than the budget.Lower Max length or Max tokens (the reserve), raise the context size if the model allows, or trim the system prompt, the card and the lore budget. See Context and budget.
The server's own "context length" or "too long" errorThe model's real window was smaller than the estimate assumed.Ashyo trims and resends once by itself. If it still fails, set a smaller Context size by hand.

If replies seem to forget early events, the chat has simply grown past the window. The "last prompt starts here" divider in the transcript shows where the model's view began, and a reply's itemization lists exactly what was dropped. Lore books are the tool for keeping facts alive past that point, see Lore books.

Files, saving and imports

MessageMeaningWhat to do
"Could not save <chat>: …"Writing the chat file failed. Nothing is lost: the changes stay in memory and Ashyo retries every few seconds.Free disk space or fix permissions on the chats folder, then keep working; the next retry succeeds. The message shows once per failure.
"Could not load <chat>: …" or "Could not load the other branches of <chat>: …"The chat file could not be read, or its side branches could not. In the second case the chat stays open on its current branch with a notice, and closes itself once nothing is generating or being edited.Check the file named; see below for version and integrity messages.
"chat … has format version N, not the M this app reads"The file was written by a different version of Ashyo. Nothing is converted automatically.Open it with the version that wrote it.
"… is not valid"The chat file failed an integrity check on opening.Restore it from a backup; the file is not modified.
"Not a transcript Ashyo can read." or "No file at …"The file you tried to import is not a SillyTavern JSONL or ShareGPT transcript, or is gone.See Importing transcripts for the formats that work.
"The PNG has no embedded character card.", "The PNG character card data could not be decoded.", "Not a character card: expected JSON or a PNG card.", "The character card has no name.", "Not a valid item file."The file is not a card or an Ashyo item in a form Ashyo recognizes.Re-export the card from its source; a card needs at least a name. See Character cards.
"Cannot write <path>: …" or "Cannot open <dir>: …" in red in the file dialogAn export could not be written, or a folder could not be listed.Pick a folder you can write to; the dialog remembers the folder you were in for next time.
"Name is required.", "Name already exists.", "Cannot delete the default …", "Cannot rename the built-in …"Library names must be unique and non-blank, and the five built-in defaults and templates stay.Choose another name, or Save as a copy of a built-in to change it freely.
"input history: …; messages are sent as usual and nothing is recalled"The input history file could not be read at startup.Sending still works; delete or repair history.jsonl to get recall back.
"Could not read ashyo.log: …"The Log file tab of the log viewer could not open the file.Check the file's permissions.

A field refuses a value

Settings rows check what you type before saving it. The refusal appears in red under the field and names the row: "{Field} is required.", "{Field} must be one of: …", "{Field} must be true or false.", "{Field} must be an integer." or "must be a number.", "{Field} must be between X and Y.", "{Field} must be X or higher." or "X or lower.", "{Field} can hold at most N entries.", "{Field} must be a JSON object.", "Invalid value for {Field}.", "Invalid JSON: …" and ""x" is not a number." Each row's note shows its limits as "min X · max Y · step Z". Commands have their own refusals above the composer: "usage: /model <id>" when a command gets the wrong number of words, "no message #N; the chat has K messages" for a number out of range, and for labels in the turn tree "Label must not be empty." and "Label is N columns wide; at most 48 are allowed."

Copy and paste

Copying never needs a helper program: Ashyo hands the text to your terminal, which puts it on the clipboard, and this works over SSH when the terminal allows it. The status bar confirms with "copied". If nothing lands on the clipboard, the terminal is blocking that feature; most terminals have a setting to allow it.

Pasting is the other way around. Ctrl+V asks the system for the clipboard through pbpaste, wl-paste, xclip, xsel or termux-clipboard-get, whichever is installed, and finally asks the terminal itself. "No clipboard tool is installed." means none of those worked: install your desktop's clipboard tool (wl-clipboard on Wayland, xclip or xsel on X11), or simply use your terminal's own paste shortcut, which Ashyo always accepts wherever text can be typed.

Known limitations

  • OpenRouter fallback is fenced in. Hosts you list under Model providers go out as a strict allow-list, so Allow fallback providers cannot route to a host outside them. Leave the list empty if you want OpenRouter free to fall back anywhere.
  • Only HTTP proxies. Ashyo honors HTTP CONNECT proxies from the environment; SOCKS proxies are not supported.
  • Old card placeholders stay as written. A character card using <USER>, <BOT> or <CHAR> is imported as is; only {{user}} and {{char}} are expanded. Edit the card's text after importing.
  • An unbalanced asterisk is shown as typed. A finished reply with a stray * is not italicized or corrected.
  • Code inside a list item renders wrongly. A fenced code block nested in a bullet point is not drawn correctly by the markdown renderer.

When the message is not enough

Everything Ashyo does is written to ashyo.log in the data folder at the level set by the Log level row on the General tab of Settings: info by default, debug or trace when you are chasing a problem, off to record nothing. Open the log viewer with /log to read this session's records live or page through the file without leaving Ashyo. Refusals you could have corrected are logged at info; real failures at error, with the provider's full answer where there was one. See Files and logs.

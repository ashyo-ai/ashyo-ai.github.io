Composer and commands

The composer is the line (or lines) you type into, sitting between two rules near the bottom of the screen. It is a small text editor with undo, selection and word movement, it remembers what you have sent before, and it is where you type slash commands such as /new or /rename. This page covers typing, sending, history and every command.

Typing and editing

A ❯ marks the first row of the composer, drawn in the accent color while the composer has focus. Typing inserts at the cursor, which is drawn as a reversed cell, and replaces the selection if there is one. The composer grows a row at a time as you write, up to half the window's height, then scrolls to keep the cursor row in view with a scrollbar on its right.

Undo has no step limit. Edits of the same kind merge into one step, so typing a word undoes as a word, and the space after a word joins that word's step; moving the cursor ends the merge. Sending, running a command or switching chats empties the composer and its undo history.

A click places the cursor and a drag selects. The mouse wheel scrolls the composer and drags the cursor along. After you type a slash command and a space, a muted hint shows the argument the command expects, right after the cursor. A field that holds a secret, such as an API key, draws every character as a •.

What you have typed is saved with the chat after a second's pause, so a half-written message survives leaving the chat or quitting; see Drafts.

Sending

Press Enter to send. The composer empties, the completion dock closes, and your message appears in the transcript with the reply streaming in under it. While a reply is generating, Enter does nothing and your text stays put. While a long chat is still loading, sending is refused with "The chat is still loading."

  • Enter on an empty composer asks for a reply without adding a message of your own. This is how you get the character to speak again, or to go first.
  • ← and → on an empty composer, while nothing is generating, swipe the last reply; → past the last swipe generates a new one. See Swipes.
  • Esc while a reply is generating stops it. The text that arrived so far is kept; see Streaming.
  • With no chat open, sending is refused with "no chat is open; press ctrl+s to pick a chat" and the composer is cleared. While a chat is still opening you see "the chat is still opening".

Refusals, such as a mistyped command, an unknown command or a message number out of range, show in red on the notice line just above the composer. Esc dismisses a refusal; with text in the composer it does nothing more than that. Commands always go into your input history; plain messages go in only when the chat was not busy.

Tip

Sending plain text is one of four ways to generate. The others are swiping, continuing a reply, and /sysgen. What each one sends to the model is described in Prompt building.

Input history

Everything you send, messages and commands alike, is remembered across sessions in a history file (see Files and logs). Blank input is skipped, a repeat moves to the front, and the list holds the most recent 1,000 entries.

With an empty composer, ↑ brings back the previous entry and ↓ the next; ↓ past the newest empties the composer again. While a recalled entry is shown you can keep stepping, and the moment you edit it the arrows go back to moving the cursor.

For a longer look, Alt+H opens the history dock under the composer. It lists every entry that contains what you have typed so far (ignoring case), multi-line entries flattened to one row, each with its age: "now", then seconds, minutes, hours, days or years as "5m", "3h", "2d". Tab or Enter puts the highlighted entry in the composer.

If the history file cannot be read at startup you see "input history: …; messages are sent as usual and nothing is recalled" once, and Ashyo carries on without it.

Command completion

Type / as the first character and the completion dock opens under the composer with every command in alphabetical order, each with a one-line description and, where the dock is wide enough, a muted hint on the right. Keep typing and the list narrows to the commands that match. The highlighted row gets a band and a ❯.

↑ / ↓
Move the highlight.
PageUp / PageDown
Scroll the list.
Tab
Accept the highlighted command, adding a space after it when it takes an argument.
Enter
Accept and run it at once.
Esc
Close the dock and keep what you typed.

The dock is rebuilt after every edit, closes when your text runs to more than one line, and only opens when there is room for it under the composer. Commands with a fixed set of values, which today means only /chat temp, complete their value by substring too.

Model dock

Press Ctrl+P on an empty composer, or run /model, to switch models without leaving the chat. The dock shows "Loading models..." while it asks the chat's connection for its list, then one row per model: the name, a • on the model the chat uses now, the id when it differs from the name, and the model's context size as "N context". Type to filter by id or name; "No matches for "x"." or "No models." tell you when nothing fits. The list shows at most 100 rows. Enter sets the highlighted model for this chat and clears the composer. If the list cannot be fetched, the failure is reported on the notice line.

Slash commands

A command is a line starting with /. Commands that act on a chat need one open. A command that is waiting for the chat to become free, such as /delete during a generation, keeps its text in the composer until it can run. Angle brackets mark an argument; square brackets mark an optional one.

CommandWhat it does
/model [<id>]Opens the model dock, or with an id switches this chat straight to that model for later turns. Extra words are refused with "usage: /model <id>".
/rename <title>Renames the chat. Hidden in a temporary chat, where it is treated as unknown.
/newStarts a new chat with your default settings and shows it, leaving the current one open in the background. See Open chats.
/chatOpens the chat picker, the same as Ctrl+S.
/chat tempStarts a temporary chat that is never written to disk. Any other argument is refused.
/closeCloses this chat and shows the next open one, or the picker. Refused while a reply is streaming.
/treeOpens the turn tree. Waits while the chat is loading.
/goto <n>Marks message n and scrolls it into view, moving focus to the transcript. A message still being sent counts as a number. Waits while the chat is partly loaded.
/delete <n,n-m>Deletes messages by number. Waits while the chat is busy.
/disable <n,n-m>Disables messages by number. A disabled message stays in the transcript, labeled "Disabled", but is left out of the prompt. Waits while busy.
/enable <n,n-m>Enables messages by number again. Waits while busy.
/send <text>Adds a message from you without asking for a reply. Waits while busy.
/sendas <text>Adds a message as the character without asking for a reply. Waits while busy.
/sys <text>Adds a system message without asking for a reply. Waits while busy.
/sysgen <prompt>Asks the model to write a system message from your prompt, for narration or scene changes. See /sysgen. Waits while busy.
/inspectorTurns the prompt inspector on or off for this chat. In the completion dock its description reads "Inspector: on" or "Inspector: off" to show the current state.
/settingsOpens Settings.
/libraryOpens the Library.
/logOpens the log viewer.
/quitSaves every chat and exits. While a reply is generating or a message edit is open it asks first; see the quit question.

A command that takes no argument refuses one, a command that takes text refuses an empty one, and anything else starting with / is refused as unknown.

Message numbers

With Show message indices on (the default), every message header starts with its number, counting the visible messages of the current branch from 1. /delete, /disable, /enable and /goto take these numbers. A list may hold single numbers and ranges separated by commas, and a range may run backwards, so 3,7-9,12-10 means messages 3, 7, 8, 9, 10, 11 and 12. Duplicates are merged. A number past the end is refused with "no message #N; the chat has K messages". While a long chat is still loading, the numbers already account for the messages not loaded yet.

Focus and global keys

Keys always go to the part of the screen that has focus: the composer or the transcript. Ctrl+↑ moves focus up into the transcript and Ctrl+↓ back down to the composer; a click does the same. Moving focus clears the transcript's mark. A few keys work the same from either place:

Esc
Steps down a ladder: clears the mark or range in the transcript if there is one; otherwise stops a generation if one is running; otherwise, on an empty composer, opens the turn tree. There are no timed key sequences.
Ctrl+S
Opens the chat picker.
Ctrl+P
Opens the model dock when the composer is empty.
Alt+H
Opens the history dock.
Ctrl+O
Folds or unfolds every reasoning block in the transcript. See Reasoning.
PageUp / PageDown
Scroll the composer when it has overflowed; otherwise move the transcript's mark by a screen when one is set; otherwise scroll the transcript.
Ctrl+Home / Ctrl+End
Jump the transcript to its top or bottom.

While any chat is being saved, or the window is too small, every key is ignored. Any key clears the notice line. Keybindings cannot be changed, and there is no key help inside the app, so the Keyboard reference lists them all.

Files and logs

Everything Ashyo knows about you lives in a handful of files on your own disk: one settings file, one file per chat, one file of accounts, your input history and a log. This page tells you where each one is, what is in it, what is safe to touch by hand, and how to read the log when something needs explaining.

Where everything lives

Ashyo follows the XDG base directories. Your settings go under XDG_CONFIG_HOME and your data under XDG_DATA_HOME; when a variable is unset, or set to a relative path, which Ashyo ignores, the usual defaults under your home folder apply. Both folders are created at startup if they are missing. If neither XDG_CONFIG_HOME nor HOME is set, Ashyo cannot start and says so.

WhatDefault path
Settings and library~/.config/ashyo/ashyo.json
Chats, one file each~/.local/share/ashyo/chats/*.db
Accounts and keys~/.local/share/ashyo/auth.json
Input history~/.local/share/ashyo/history.jsonl
File dialog memory~/.local/share/ashyo/file-dialog.json
Log~/.local/share/ashyo/ashyo.log

To back Ashyo up, copy the two folders. To move to another machine, copy them there. Nothing else is stored anywhere.

The settings file

ashyo.json holds your whole Library, every preset, persona, character, lore book and regex script, together with the app-wide settings from the General and Appearance tabs, the defaults new chats start from, and a few values that have no row on screen. Ashyo writes it every time you change something, so there is no save step and nothing to lose if the power goes.

The file is sparse: only values that differ from Ashyo's defaults and built-ins are written, and a built-in item you never changed does not appear at all. A missing file simply means the built-in defaults, which is why a first run opens Settings. There is no migration from older layouts.

Two settings exist only in the file, under a backend key, because almost nobody needs them: connect_timeout, how many seconds to wait for a server to accept a connection (30), and read_timeout, how many seconds of silence end a request (300). A sampler_globals key holds the Global bans list that is applied under every text sampler preset, which you can also edit on the Samplers tab.

Editing it by hand

You can, but quit Ashyo first: the app rewrites the file on every change, and it would overwrite your edit. Ashyo is strict when it reads the file back. A key it does not know, a duplicate name, a persona or character naming a lore book or regex script that does not exist, a value out of range or of the wrong type: any of these stops startup with a message that names the problem and where it is, such as "missing required config key at …" or "duplicate config name "Ada" at …". Nothing is repaired or dropped for you. Fix the file, or move it aside to start fresh.

Heads up

The settings file is the only place your library exists. A character you delete in the Library is gone from the file at the next write, and there is no undo. Copy ashyo.json somewhere safe before a big reorganization, or export the items you care about as Ashyo item files.

Accounts and keys

Credentials are kept apart from everything else in auth.json, so you can share or back up your settings file without handing out your keys. The file lists your accounts per provider, each holding either an API key, a login for OpenAI Codex, or nothing. A missing file means no accounts. You never edit it: keys are pasted and logins run from the Connection settings, and the file is written for you with permissions that keep it private.

Ashyo refuses to read a credentials file that anyone else could: it must be a regular file, not a symlink, and must not be readable by the group or by others. The folder around it is created private as well. If you copied the file over and the permissions came along too loose, Ashyo tells you, "permissions 0644 expose credentials; require 0600", and the fix is chmod 600 ~/.local/share/ashyo/auth.json.

Account names have their spaces collapsed, must not be empty, and must be unique within a provider. They are listed alphabetically, ignoring case. Removing the last account of a provider removes that provider's section; logging out or clearing a key leaves the account in place with no credential. Renaming or removing an account carries through to every preset, the defaults and every chat that named it.

Chat files

Each chat is one SQLite file in the chats folder, named from its creation time and the start of its id, for example 2026-10-22_14-03-27Z_3f2a1b9c.db. The name never changes, even when you rename the chat inside Ashyo. The file holds the chat's name, settings, draft and every turn and message on every branch, along with the prompt records the itemization reads.

The chats folder is scanned when Ashyo starts and again whenever you open the picker, so you can drop a chat file from another machine into it and open it. The picker remembers chats it has already seen and only rereads files whose size or modification time changed; a file it cannot read is skipped with a warning in the log. Deleting a chat from the picker deletes its file.

Ashyo checks a chat before it trusts it. A file written by a different version of the format is refused, naming the version it found and the one this app reads. A file whose contents do not hang together, with a message pointing nowhere or a branch leading in a circle, is refused with " is not valid", for example "a turn's parent is not valid". Chats on disk are never rewritten to repair them.

Input history

Everything you send from the composer, messages and commands alike, is appended to history.jsonl, newest first in the list Ashyo keeps, so you can recall it with ↑ and ↓ on an empty composer or search it with Alt+H. A repeated entry moves to the front rather than appearing twice, blank input is skipped, and the list is capped at 1,000 entries. The file is private to your user. Lines Ashyo cannot read are ignored, and a file cut off mid-line is repaired on the next write.

If the history cannot be loaded at startup, Ashyo says so once, "input history: …; messages are sent as usual and nothing is recalled", and carries on. A write that fails still updates what you can recall in the running session. See Input history for the keys.

Logging

Ashyo keeps a log of what it does in ashyo.log. How much goes in is set by the Log level row on the General tab of Settings: off, error, warn, info, debug or trace, with info as the default. The row describes itself as "Choose how much Ashyo records in ashyo.log and the log viewer. Off records nothing." A change applies at once, no restart needed.

The log file is the only place log lines go; nothing is printed to the terminal while Ashyo runs. Each line reads as a UTC time with microseconds, the level, which part of Ashyo wrote it, and the message. Every generation adds one summary line. Things you can correct yourself, such as a refused command, are logged at info; real failures at error. Lines written before the settings file has been read are held back and written once the level is known. Logging from the libraries Ashyo is built on is capped at warn so it does not drown your own lines.

If the log file cannot be opened at startup, Ashyo does not start unless the level is off. If it becomes unwritable while running, the level you chose is kept, the log viewer shows ": " in red on its notice line, and the file is tried again the next time you change the level.

debug and trace are for when something needs explaining and you want the detail in the log; day to day, info is plenty.

The log viewer

/log opens the Log viewer, a box with two tabs. Switch with Tab or by clicking a tab name. With logging off, the viewer simply says "Logging is off; set Log level in Settings to turn it on."

This session

The This session tab shows the records of the running session, colored by level, with a list of the parts of Ashyo that have logged something. Every level of every part is kept here regardless of what reached the file; the Log level row alone decides what the viewer and the file receive at all.

↑ / ↓
Pick a part in the list.
← / →
Change the level shown for the picked part.
f
Show only the picked part.
Space
Hide the parts whose level is set to off.
h
Hide the list of parts.
PageUp / PageDown
Scroll back through older records.
Esc
Leave the scrollback first, then close the viewer.

Log file

The Log file tab reads the last 10,000 lines of ashyo.log each time you switch to it, and opens at the bottom, noting when the file was cut. A file that cannot be read shows "Could not read ashyo.log: …". Press / to search, type the query and press Enter; n and N step to the next and previous match, wrapping around, with matches highlighted and the current one in bold. The query survives reloading the tab. Ctrl+A selects everything, the mouse selects by dragging and the wheel scrolls, and Ctrl+C copies the selection. The footer reads "/: find, n/N: next/previous match, esc: close".

Starting and stopping

  • First run. With no settings file, Ashyo opens Settings on the Connection tab with "Set up a connection to start chatting." See First run.
  • One copy at a time. Ashyo locks its settings and data folders while it runs. Starting a second copy against the same folders is refused with "Another copy of Ashyo is already running."
  • Quitting. /quit saves every chat and leaves. Closing the terminal, which sends a hangup signal, or a termination signal from the system, does the same, so an accidentally closed window does not lose a chat. See How saving works.
  • Errors. Anything that stops Ashyo from starting or shutting down cleanly prints to the terminal as "ashyo: …" with the full chain of causes, and the process exits with status 1. The screen is always restored first.
  • Version. ashyo --version prints "ashyo 0.1.0 ()", with "-dirty" after the commit when the build had uncommitted changes. It is the only command line option; anything else is refused with "ashyo: unknown option " and exit status 2.

For what the messages mean and what to do about them, see Troubleshooting.

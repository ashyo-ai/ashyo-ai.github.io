Tools

Ashyo ships a fixed set of seventeen tools and no way to add more. Every call goes through the same policy and hook path, and the model is told when a result was cut short.

Tool definitions are sent to the provider in strict mode. A required argument that is missing or null comes back to the model as tool_error naming the argument, and the tool does not run.

Paths

File tools resolve paths against the workspace root and your home directory. A path outside both is refused with path_outside_workspace. Named pipes, sockets, and devices are refused by read, edit, and grep, so a tool cannot be parked forever on a FIFO.

Limits

Every limit that cuts a result short is announced to the model in the result itself, so a partial file never reads as the whole file.

shell

The command string is passed to bash -lc unchanged, in the session's working directory unless cwd is given, as your user, with your environment. There is no allow-list and no argument parsing; the rule engine sees the whole string at /command, which is what makes a regex rule meaningful. Output is the tail of stdout and stderr with the exit code. A timeout ends the command and says so.

Web tools

web_search queries DuckDuckGo's HTML endpoint and parses the results; a CAPTCHA page or a non-2xx response is a visible tool error, not an empty result. With webSearch.backend set to auto, the provider's own search is offered to the model when the provider supports one, and Ashyo falls back to the local tool if the provider rejects it. Set duckduckgo to always use the local tool. web_fetch reads a page as text and is the way to open a search result.

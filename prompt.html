Prompt building

Every reply starts with a prompt Ashyo builds for the model: the system prompt, your persona, the character, whatever lore fired, and the chat so far. Three presets shape it. The system prompt is the instructions, the context template decides which pieces go in, in what order and how they are cleaned up, and the instruct template turns it all into the exact text a text-completions model expects. This page explains each piece and what happens between pressing Enter and seeing a reply.

What goes into a prompt

A prompt is assembled from items. Empty items are simply left out, so a character with no scenario does not produce an empty section.

  • System prompt. The chat's system prompt preset, or the card's own when it wins. See The system prompt.
  • Persona. Your persona's description.
  • Character. The description and personality, then the example messages. See Personas and characters.
  • Scenario. The character's scenario.
  • Lore. Entries that fired, each at its position: early, late, before or after the examples, at a depth inside the history, or in an outlet. See Lore books.
  • Chat history. The current swipe of every enabled turn on the branch you are on, oldest first. Disabled messages are skipped. See Swipes and branches.
  • Post-history instructions. Only when the card has them and you prefer them; placed after the history.
  • User filler message. Text completions only; see Text completions.
  • The /sysgen prompt. Only on a /sysgen generation; see Generating a system message.

The system prompt, persona, character, scenario and the early and late lore come from the context template's rows and sit at the top of the prompt in row order. The history follows, with lore at depth slotted into it, and then anything that goes after the history. How that list becomes a request depends on the connection's protocol. With chat completions the model receives a list of messages, each with a role. With text completions it receives one string, and the instruct template writes it. The presets are chosen on the Prompt tab of Settings and edited in the Library.

Tip

Turn on /inspector and every send pauses to show you the finished prompt before it leaves. Once a reply has arrived, Itemization in its message menu breaks the prompt it came from into items with token counts. See Context and budget.

What happens when you press Enter

There are four kinds of generation. Send is what Enter does with text in the composer. Swipe asks for an alternative to the last reply. Continue extends the last reply. /sysgen generates a system message from a prompt you type. For a send, the steps are:

  1. Your text goes through your regex scripts that target Your messages, then macros expand, then the context formatting switches apply. What you see in the transcript is this finished text.
  2. It is added to the chat as a new user turn. An empty send skips this step and just asks for a reply.
  3. Ashyo checks the connection has what it needs: credentials and a reachable address. If the context size is not known yet it is fetched now, and a send fails with "unknown context size" if the server cannot say.
  4. The prompt is planned against the budget: lore is activated, items are gathered, and older history is evicted until it fits. If the inspector is on, this is where you see the prompt and press Enter to approve it; what you approved is sent unchanged.
  5. The reply streams into the transcript. When it is done the chat's context usage on the status bar updates, and the reply remembers which provider and model answered.

A swipe adds an alternative to the last turn. It is refused when the turn already holds as many swipes as it can, and only the last turn can be swiped. A continue works on text completions only: trailing whitespace is trimmed off the newest reply and the model is asked to carry on from there, so the new text lands in the same message. If that reply is shared with another branch, your branch gets its own copy and the continue writes into that.

How replies are cleaned up

Text streams in raw, and a few things happen to it on the way:

  • Reasoning is split off. A chat-completions server sends reasoning separately. For text completions, the instruct template's Reasoning prefix and Reasoning suffix mark where reasoning ends and the reply begins, and Ashyo separates the two even when a marker arrives in pieces.
  • Strip the character's name from replies (on by default). A reply that begins with the character's name and a colon loses that label. Ashyo holds the first few characters back until it can tell.
  • End replies where the persona speaks (on). If the model starts a line with your persona's name and a colon, the reply ends right there and the server is told to stop. A continue keeps the text it started from but still ends at such a line.
  • Regex scripts targeting Replies and Reasoning run once the reply is complete. On a continue only the new text is rewritten.
  • Output cleanup. The context template's Normalize whitespace, Trim spaces and Trim incomplete sentences apply to the finished reply. See Context formatting.

The reply also records when its first token arrived, how long the reply and the reasoning took, and how many tokens the server counted; a continue adds to the earlier figures. The message card can show all of that.

Stopping a reply

Press Esc while a reply is streaming to stop it. If any text had arrived it is kept as the reply. If nothing had arrived yet, there is nothing to keep and the reply is discarded, as is a reply the model finished without saying anything. Deleting a chat or discarding a temporary chat stops its stream first. Closing a chat is refused while it is streaming.

One retry happens without you: if the server reports that the prompt was too long, Ashyo plans it again with a little more room and sends once more. See Eviction.

Settings are frozen at send time

The moment a generation starts, it takes a copy of everything it needs: provider, model, protocol, samplers, routing, base URL, extra request fields, the instruct template, the context template's rows, separators, squash and post-processing choices, and the display names of your persona and character. Changing a setting while a reply streams affects the next generation, not the one in flight.

The system prompt

The system prompt is the standing instruction at the top of the prompt. Each chat selects a System prompt preset from the Library, and you can edit the text for this chat alone on the Prompt tab, which shows "Preset: N characters" once you have. The built-in preset named Default is empty, so a fresh install sends no system prompt until you write one. See System prompts in the Library.

A character card can carry its own system prompt and post-history instructions. Turn on Prefer the card's system prompt for the character and, as long as the card's prompt is not blank, it replaces the chat's. The Prompt tab then notes "The character's card supplies the system prompt; this one is not used." Write {{original}} inside the card's prompt to drop the chat's prompt in at that spot, and the note changes to "The character's card supplies the system prompt; this one is used only where the card writes {{original}}." Prefer the card's post-history instructions works the same way for the text placed after the chat history. Both switches live on the character and can be overridden per chat. See A card's own prompts.

The context template

The context template decides what sits above the chat history and how the whole prompt is tidied. Its Rows are a checkbox list you can reorder with Move up and Move down; each row has a prefix you set with Edit prefix, text placed in front of that row's content, with macros expanded. The built-in template named Default has the six rows below in this order and no prefixes.

RowWhat it adds
System promptThe system prompt described above.
Lore (early)Lore entries positioned Before character. Always on.
PersonaYour persona's description.
CharacterThe character's description, then personality, then the example messages with any lore positioned around them.
ScenarioThe character's scenario.
Lore (late)Lore entries positioned After character. Always on.

The two lore rows cannot be turned off; every other row can. Each section appears once no matter how many rows name it. Templates are edited in place, so a change to one applies to every chat that uses it.

Example messages

A character's example messages show the model how a conversation with it should sound. Each example is a block, and inside a block a line that starts with your persona's name and a colon begins a message from you, while a line starting with the character's name and a colon begins a message from the character. Write them as {{user}}: and {{char}}: and the macros become the right names. Lines that follow without a speaker join the message above. A block with no speaker lines at all is sent as one system message. Lore entries positioned Before examples or After examples are split into blocks the same way wherever their content contains <START>.

{{user}}: Do you ever leave the forest?
{{char}}: *She tilts her head, considering.* "Leave? The forest is not a place
I am in. It is a thing I am." She smiles. "But I do like to hear about elsewhere."

In chat completions each speaker line becomes its own message with the matching role. In text completions each block is preceded by the Example separator. Examples are the first thing to go when the prompt is over budget, so a long chat may not include them. See Eviction.

The other template fields

  • Squash system messages (on). Chat completions only. Consecutive system messages are joined into one with a blank line between them, so the rows above the history arrive as a single system message. Example messages are never squashed.
  • Prompt post-processing (None). Chat completions only; see Post-processing.
  • Example separator and Chat start. Text completions only. The first goes before each example block, the second before the first message of the history.
  • Separators as stop strings (off) and Names as stop strings (on). Text completions only; see Stop strings.
  • Strip the character's name from replies (on) and End replies where the persona speaks (on). See How replies are cleaned up.
  • Normalize whitespace (off), Trim spaces (on) and Trim incomplete sentences (off). See Context formatting.

Chat completions

With a chat-completions connection the prompt is a list of messages, each tagged system, user or assistant. The template rows become system messages at the top, with a row's prefix placed in front of its first item. Example messages become user and assistant messages (or a system message for a block without speakers). The history follows with its own roles, and lore At depth is slotted in between the messages with the role you gave it. Here is the shape of one, before squashing:

system     You are a storyteller. Write {{char}}'s next reply…      System prompt row
system     The Vale is a cold northern valley…                      Lore (early)
system     Ada is a wandering cartographer…                         Persona
system     Seraphina is a guardian of the forest…                   Character
system     The two meet at the edge of the Vale.                    Scenario
user       Hello? Is anyone there?                                  history
assistant  "Welcome, traveler."                                     history
system     A storm is rolling in from the north.                    lore at depth 1
user       Is there shelter nearby?                                 newest message

With Squash system messages on, the five system messages at the top travel as one. A /sysgen prompt is a system message after the history, and post-history instructions go there too.

Post-processing

Some servers are strict about which roles may follow which. Prompt post-processing reshapes the finished list to suit them:

ModeWhat it does
None (default)The list is sent as built.
Merge consecutiveNeighboring messages with the same role are joined into one.
Semi-strictMerge, then every system message after the first becomes a user message, then merge again.
StrictSemi-strict, and if the leading system message is not followed by a user message, a user message reading "[Start a new chat]" is inserted.
Single user messageEverything is folded into one user message, each part labeled "Name: " with its speaker.

Text completions

A text-completions model receives one block of text and continues it, so the prompt has to spell out who is speaking with the markers that model was trained on. That is the instruct template's job. The pieces go in this order:

  1. The story string: the Story string prefix, then every template row's prefix and content joined by line breaks, then the Story string suffix. If there is nothing to put in it, the whole story string is omitted.
  2. The example messages, each block preceded by the Example separator, with any lore placed around them.
  3. The Chat start text, then the history. Each message is wrapped in its role's prefix and suffix sequences.
  4. Anything placed after the history, such as post-history instructions or a /sysgen prompt.
  5. The generation prefix, which opens the model's turn and leaves it unfinished for the model to complete.

With the built-in ChatML template, which wraps its sequences in line breaks, a short chat renders like this:

<|im_start|>system
You are a storyteller. Write Seraphina's next reply…
Ada is a wandering cartographer…
Seraphina is a guardian of the forest…
The two meet at the edge of the Vale.<|im_end|>
<|im_start|>user
Hello? Is anyone there?<|im_end|>
<|im_start|>assistant
"Welcome, traveler."<|im_end|>
<|im_start|>user
Is there shelter nearby?<|im_end|>
<|im_start|>assistant

A few rules fill in the details. Reply content is trimmed of surrounding whitespace. Speaker names are the name recorded on each message, or failing that the current persona, the character, or "System". The User filler message, when the template has one, is a user turn inserted where the history would otherwise open with the model speaking: at the start of the history, or before the /sysgen prompt, or at the very end when there are no messages. Some models refuse to begin with their own turn, and the filler gives them a user turn to answer.

The generation prefix is the Assistant prefix for turn end if the template has one, otherwise the Assistant prefix. With Emit empty reasoning at turn end on, an empty reasoning block (the reasoning prefix followed at once by the suffix) is appended so the model skips its thinking. If Include names is Always, the character's name and a colon follow. On a continue there is no generation prefix at all: the last message is left open with no suffix, and the model carries on from its last word.

The instruct template

Instruct templates apply to text completions only; a chat-completions server does its own formatting. Ashyo ships templates for the common model families, listed under Built-ins, and Raw role labels is the default, writing plain "User:", "Assistant:" and "System:" labels. The fields:

FieldDefaultWhat it does
Sequences as stop stringsonSend the user, assistant and system prefixes as stop strings, so the model stops when it starts someone else's turn.
Wrap sequences in newlinesoffPut a line break after every prefix, and use a line break where a suffix is empty.
Include namesPast participantsWhether "Name: " precedes each message. Always, Never, or Past participants: only speakers other than your current persona and character, which keeps old names straight after you switch character or persona.
System uses the same format as useroffWrap system messages in the user prefix and suffix instead of the system ones.
User prefix, User suffixemptyThe text around each of your messages.
User filler messageemptyA stand-in user turn for a history that would otherwise begin with the model. See above.
Assistant prefix, Assistant suffixemptyThe text around each reply.
Assistant prefix for turn endemptyA different prefix for the generation prefix only, when the model wants its last turn opened differently.
System prefix, System suffixemptyThe text around system messages inside the history, such as lore at depth.
Story string prefix, Story string suffixemptyThe text around the story string at the top.
Stop sequenceemptyOne or more strings that end the reply, on top of those derived from the sequences.
Reasoning prefix, Reasoning suffixemptyThe markers a thinking model puts around its reasoning, so Ashyo can split it from the reply.
Emit empty reasoning at turn endoffAppend an empty reasoning block to the generation prefix to skip the model's thinking.

SillyTavern instruct presets import as Ashyo instruct templates, including their reasoning markers. See Import and export.

Where things land in the history

Items that are not template rows have one of three placements. Top items follow the template's row order. At depth N items are inserted before the Nth-newest message, or before the oldest message when the history is shorter than N. After history items, and depth 0, go after the newest message. Lore At depth uses the second placement; post-history instructions and the /sysgen prompt use the third.

When several items want the same spot, the deeper ones go first, then assistant, user and system items in that order. In text completions, consecutive placed items with the same placement and role merge into one turn. On a text-completions continue, depth 0 and after-history items are placed before the message being continued, so the model's open turn stays last.

Context formatting

Three switches on the context template tidy text wherever Ashyo formats it: your sends, the model's replies, greetings, lore content and the character and persona fields.

  • Normalize whitespace (off). Runs of blank lines are capped at one blank line, and leading and trailing whitespace is removed.
  • Trim spaces (on). Whitespace at the start and end is removed.
  • Trim incomplete sentences (off). Text is cut after its last sentence end: a period, exclamation mark, question mark or ellipsis, along with any closing quote, bracket or asterisk that follows it. A model that stops mid-sentence at its token limit loses the dangling fragment.

Stop strings

A stop string tells the server to end the reply the moment it produces that text. With chat completions, only the Stop list from your samplers is sent. With text completions, Ashyo combines several sources and removes duplicates:

  • The samplers' Stop list.
  • The instruct template's Stop sequence.
  • With Sequences as stop strings on: each line of the User prefix, Assistant prefix, Assistant prefix for turn end and System prefix.
  • With Names as stop strings on: a line break followed by your persona's name and a colon, so the model cannot start speaking for you.
  • With Separators as stop strings on: a line break followed by the Chat start text, and one followed by the Example separator, when they are not empty.

Banned tokens work alongside them: the global bans from the samplers' Global bans row go out ahead of the chat's own on every text-completions request. See Samplers.

Generating a system message

/sysgen <prompt> asks the model to write a system message rather than a reply in character, which is handy for a narrator's summary, a scene change or a note to itself. The prompt you type becomes a system item after the chat history that is never evicted, the model generates as System rather than as the character, and the result is added to the chat as a system message. Lore entries can be limited to, or kept out of, these generations with the /sysgen generation type. To add a system message you write yourself, use /sys <text> instead; see Composer and commands.

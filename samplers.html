Samplers

A model does not pick its next word with certainty; it weighs every candidate and chooses among the likely ones. Samplers are the knobs on that choice: how adventurous the pick is, how many candidates stay in the running, how hard repetition is punished, where the reply must stop. Ashyo keeps them in presets so a setup you like follows you from chat to chat.

Where samplers live

Samplers are on the Samplers tab of Settings (/settings). The tab appears once your connection has a protocol; until a provider is chosen it only says "Select a provider to set its samplers." Because Chat Completions and Text Completions accept different knobs, there are two kinds of sampler preset, each with its own tab in the Library: Sampler presets (chat) and Sampler presets (text). The chat's protocol decides which kind the tab shows, with the header reading "Preset (Text Completions)" or "Preset (Chat Completions)".

Ashyo ships no sampler presets. The defaults listed below are built in and never saved, so an empty preset means "use the defaults". When you change a row in a chat, it becomes an override marked "∗ " with a note reading "Default: X" or "Preset: X", and a Reset action puts it back. Press Tab on the preset row for the preset actions:

  • Save. Write the chat's overrides into the selected preset and clear them. Offered only when a preset is selected and something changed.
  • Save as. Make a new preset from the selection plus overrides, named "Untitled" until you rename it, and select it.
  • Rename and Delete. Delete asks "Delete preset?" first.
  • Reset all. Drop every override so the chat follows its preset again.
  • Neutralize. Set every sampler back to the built-in default, which is the usual way to get a "clean" baseline before tuning.

The status bar confirms a save with "saved preset". Switching presets while you have unsaved changes asks whether to Discard and switch, Save then switch, or Cancel. Each row's note shows its default and its limits as "min 0 · max 1 · step 0.01", and the value you see is exactly what will be sent.

Tip

You can also edit a preset itself on its Library tab, where every field shows its limits. Chats that select the preset and have no override of their own pick up the change at once.

Two more values travel with every text request but have no row: render special (off) and trim stop (on), which keep special tokens out of the reply and cut the stop string off its end.

Sampler order

With Text Completions, the Sampler order row decides the sequence in which seven samplers apply: Top K, Top A, Top P, TFS, Typical P, Temperature and Repetition penalty. It shows as "Repetition penalty > Top K > Top A > TFS > Typical P > Top P > Temperature" by default, which applies temperature last. The row is edited as a JSON list of the seven positions numbered 0 to 6 in the order above, so the default is [6, 0, 1, 3, 4, 2, 5]. A number you leave out is appended at the end; duplicates and unknown numbers are dropped.

Max tokens and the context budget

Whatever you call it, Max length or Max tokens does double duty. Besides capping the reply, it is the generation reserve: the part of the context window Ashyo keeps free so the reply has room to land. A larger value leaves less room for chat history. The arithmetic is in Context and budget. This holds even for a provider that ignores the value itself.

Bans

Banned tokens/strings takes one entry per line and forbids each from appearing in a reply. Beneath it sits a second row, Global bans, "applied under every text-completions sampler preset": a list that goes out ahead of the preset's own bans on every Text Completions request, whichever preset the chat uses. It is the place for the handful of phrases you never want to see from any model. The global list is stored in the config file as sampler_globals, see the config file.

Stop strings end a reply the moment they appear, and Ashyo combines yours with the ones its templates imply, such as the next speaker's name. The full recipe is under Stop strings.

What gets sent

Ashyo sends only the samplers a provider supports for the protocol in use, under the names that provider expects, and always as the right kind of number. Anything unset, an empty stop or ban list, an empty grammar, an empty logit bias and a negative seed are left out rather than sent as blanks. What each provider does with the list:

  • KoboldCPP. Takes the whole text-completions list, including Sampler order, Grammar, Mirostat and the EOS switches.
  • llama.cpp and OpenAI-compatible in Text Completions. Take most of the list with a few translations. Banned tokens are sent as banned strings. Dynamic temperature range becomes a low and high temperature either side of your Temperature. DRY sequence breakers are dropped when the DRY multiplier is 0 or less, and the Adaptive fields when the Adaptive target is negative. Either EOS switch becomes a single "ignore end of text" flag. Grammar retain state, Repetition penalty slope, Sampler order and the two hidden values are skipped, since these servers have no equivalent.
  • OpenRouter. Takes the chat-completions list. Reasoning effort is passed along, and "none" turns reasoning off.
  • OpenAI Codex. Takes only Reasoning effort and Verbosity. Temperature, Top P, Top K, Top A, Min P, the penalties, Logit bias, Max tokens, Seed and Stop are all dropped. Max tokens still shapes the context budget, as described above.

The value shown on the Samplers tab is the value that goes out, already converted to what the provider expects. The prompt that accompanied a reply, though not its samplers, can be inspected afterwards through Prompt itemization.

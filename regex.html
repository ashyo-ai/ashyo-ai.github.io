Regex scripts

A regex script is a find-and-replace rule that runs on messages without you lifting a finger. Use one to tidy a model's habits, hide bits of a reply you do not want to see, change what the model is sent without changing what you read, or clean up your own messages before they go out. If you have used regex scripts in SillyTavern, these work the same way and import from cards.

What scripts do

Scripts live on the Regex scripts tab of the Library. Each one has a pattern to look for, a replacement to put in its place, a list of what it applies to and a mode that says when it runs. A script reaches a chat in one of two ways: it is marked Global, so it runs in every chat, or a character lists it, so it runs in that character's chats.

A script runs only when all three are true: it is Enabled, it has a Pattern, and it has at least one target checked under Applies to. A script that is missing any of these is simply skipped.

Pattern

Write the pattern the way you would in JavaScript or SillyTavern: /pattern/flags. You can also write a bare pattern with no slashes and no flags. The flags are any of g, i, m, s, u and y, each at most once; if what follows the last slash is not a valid set of flags, the whole text is taken as a bare pattern, slashes included.

FlagEffect
gReplace every match. Without it only the first match changes.
iIgnore case.
m^ and $ match at every line, not only the ends of the text.
s. also matches a newline.
uAccepted for compatibility; patterns always understand Unicode.
ySticky: each match must start exactly where the previous one ended.

The syntax is the Oniguruma family, so look-ahead and look-behind, backreferences, named groups and the usual classes all work. An empty match moves ahead one character and tries again, so a pattern that can match nothing does not get stuck.

Macros in pattern decides what happens to {{user}}, {{char}} and other macros written in the pattern. None leaves them as literal text, which will not match anything useful. Raw expands them and treats the result as part of the pattern, so a name containing a dot or a parenthesis is read as regex syntax. Escaped expands them and escapes the result so the name matches literally; this is what you want nearly every time.

Patterns are checked when you save a script and when Ashyo starts, and an invalid one is refused with the reason. If a pattern that passed those checks still fails while matching some text, that text is left unchanged and the failure goes to the log.

Replacement

The replacement is plain text with a few placeholders, filled in for each match:

WriteInserts
$0 or {{match}}The whole match.
$1, $2, …The numbered capture group.
$<name>The named capture group.

A group that did not take part in the match inserts nothing. Each group's text first has every Trim strings entry removed from it, then goes in. After the groups are filled, macros in the result expand, so a replacement can read $1, said {{char}}. The trim strings themselves are macro-expanded too, which lets a trim string of {{char}} strip the character's name wherever it was captured. An empty replacement deletes the match.

Targets

Applies to is a set of checkboxes. A script can target any combination:

  • Your messages. What you type and send. Also the messages added with /send.
  • Replies. What the character writes, and messages you add as the character with /sendas.
  • Reasoning. A reply's reasoning or thinking text, when the model produces any. Reasoning is never sent back to the model, so a prompt-side mode does nothing for it.
  • Lore content. The text of lore entries as it goes into the prompt. Lore is never displayed, so a display-side mode does nothing for it.

System messages are never touched by scripts.

Modes

The Mode decides when a script runs and whether its changes stick:

  • Rewrite (the default). Changes the stored text itself. Your messages are rewritten as you send them, replies when they finish generating, and lore content as it is sent. What you see and what the model sees are both the rewritten text, and it is what is saved to disk. With Run on edit on, a rewrite also runs when you save a message from the inline editor.
  • Display only. Changes what the transcript shows and nothing else. The stored text and what the model is sent stay as they were. Changing a display-only script redraws every open chat so you see the effect at once; the message still streaming is shown raw until it finishes.
  • Prompt only. Changes what the model is sent and nothing else. The transcript shows the original.
  • Display and prompt. Both of the above, still without touching the stored text.

Because lore is never displayed, a Rewrite, Prompt only or Display and prompt script targeting lore content all do the same thing: change the lore as it is sent. Because reasoning is never sent, only Rewrite and the display-side modes do anything for it.

Tip

When in doubt, start with Display only. It is reversible: turn the script off and your messages are exactly as they were. Rewrite is permanent, since it changes what is saved.

Depth

Min depth and Max depth limit a script to a slice of the conversation, counted in messages from the newest, which is depth 0. A script with Min depth 1 skips the newest message; one with Max depth 0 touches only the newest. Depth applies to the display-side and prompt-side modes. Rewrites ignore it, since they run on one message at the moment it is sent or finishes, not over the history.

When you continue a reply, only matches that start inside the newly generated text are changed, so a script does not re-run over the part of the reply you already had.

Order

When several scripts apply to the same text they run one after another, each seeing the previous one's output. Global scripts go first, in alphabetical order by name. Then the character's listed scripts go in the order they are listed on the character, which you can change with Move up and Move down. A script that is both Global and listed by the character runs once.

Scripts on cards

A character card can carry regex scripts with it. When you import such a card, Ashyo asks "Regex scripts" with the line "This card carries N regex scripts: …" and offers Leave out or Keep. Kept scripts are added to the Library under their own names (or "Character regex N" when they have none), linked to the character, and never Global. A script whose target Ashyo does not support, or whose pattern does not compile, is left out and named in the notice. Details in Character cards.

Curly quotes, display only
